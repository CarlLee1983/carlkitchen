# 瀏覽主角與配餐角色分開

2026-10-10，站主指出沙茶羊肉出現在蔬菜篩選，並確認改採「料理主角」而非「含有什麼材料」的分類。番茄炒蛋可以有雙主角，但四菜一湯與五菜一湯仍須另外保留一道蔬菜為主的菜。湯先維持現狀。

## 決定

- 保留 ADR 0002 的三種互斥 `category`，不把主食混入配飯菜候選。
- 增加 `dishKinds` 表達非湯料理的瀏覽主角：蔬菜、肉類、海鮮、蛋豆，允許真正並列的主角。首頁、卡片和 Pagefind 只使用這個欄位；主食與湯仍使用 `category`。
- 既有 `vegetable`、`protein` 明確限作配餐角色，保留抽選引擎的最小輸入形狀與套餐儲存格式。蔬菜角色只限蔬菜單主角；混合主角不得抵充套餐另外留出的蔬菜料理。仍由不同兩道菜滿足兩個角色。
- 增加必填 `classificationReason` 保存逐篇材料、做法與上桌用途的人工判據，不公開輸出。新資料不能用舊布林、自動關鍵字或未知重量比例代填。
- 每篇菜譜、包含草稿，都遷移到明確欄位。本次不改既有 `category`、`mealCandidate`、`draft`、配方、圖片和來源。四篇來源待核的草稿保持隔離。

## 選擇與代價

僅改現有兩個布林，仍會讓瀏覽雙主角與配餐蔬菜位混用，無法表達站主確認的番茄炒蛋案例。單獨改畫面文字則會隱藏配餐錯位。因此新增一個瀏覽維度，並收緊配餐角色。

沒有新增烹法、營養、飲食限制等更多維度；自由 `tags` 仍作搜尋補充，不能決定配餐角色。沒有強制每道菜只歸一類；真正雙主角需要在兩個主角篩選中可找到。

舊 `kind=vegetable`、`staple`、`soup` 網址保留，但蔬菜內容改依主角。舊 `kind=protein` 不再代表新的單一類別，按無效參數回到全部並清除，不默認成肉類。新增肉類、海鮮、蛋豆各有穩定篩選值。菜譜網址、收藏 ID、套餐儲存格式與列印流程不變。

歷史內容契約與原型票保留作決策記錄，標註已被取代的分類敘述；現行作者指南集中於 [分類指南](../recipe-classification.md) 與 GLOSSARY。全量判斷見 [逐篇審核表](../recipe-classification-review.md)。

## 驗證

schema 檢查欄位、重複值、主角與角色組合；正式內容檢查沿用同一份 schema。實際菜譜回歸涵蓋沙茶羊肉、肉燥菠菜、麻婆豆腐、番茄炒蛋及草稿隔離。首頁、卡片與搜尋共用主角映射，測有無搜尋字詞兩條路徑。抽選測四菜／五菜、角色不足、不同菜擔任不同位置、鎖定與替換不放寬規則。部署前保留至少十二菜、三湯門檻，另外驗證角色可形成套餐。

**Falsified if:** 站主需要一種料理在瀏覽上是蔬菜單主角，卻不應有蔬菜配餐角色，或需要混合主角菜取代套餐另外留出的蔬菜料理。屆時應重新審視角色契約，不放寬現有測試或依材料字詞自動補旗標。
