# 菜譜瀏覽規格：主食分類、性質篩選與手機版清單

Type: spec
Status: open
Label: ready-for-agent

## Problem Statement

站主即將大量新增菜色，其中包含台式炒麵、義大利麵、湯麵等主食。首頁清單目前只能切換「全部／非湯料理／湯」，讀者想「今天吃青菜」或「找一道麵」時只能逐列看。手機上的問題更明顯：在 390px 寬的畫面中，清單要往下捲約 910px 才開始；每列約 194px 高，因為摘要幾乎都換成 3 到 4 行；捲到清單後一個畫面只放得下 4 道菜。菜譜變多以後，手機讀者會在一條很長的清單裡捲動，而且捲到中段想換篩選時，得一路捲回頂端。

另外，主食目前在資料模型裡沒有位置。如果硬標成非湯料理，配一桌可能把炒麵抽成四菜之一。

## Solution

菜譜分類從「非湯料理／湯」擴充為「非湯料理／主食／湯」三種，彼此互斥（[ADR 0002](../../../docs/adr/0002-staple-as-category.md)）。主食不參與四菜一湯和五菜一湯。每道非湯料理至少要是蔬菜菜或蛋白質菜之一，由 schema 擋下不合規的資料。

首頁清單的篩選列改成單選的「全部｜蔬菜菜｜蛋白質菜｜主食｜湯」，兩種性質都有的菜會同時出現在兩個選項下。沒有任何已發布菜色的選項不顯示。篩選狀態寫進網址，並與搜尋並用。

手機版有三項調整：清單每列的摘要只顯示 1 行；首屏的空白收緊、成品大圖改成 2:1，讓篩選列落在第一個畫面內；捲動時篩選列固定在畫面頂部。寬螢幕版面不變。

這次不做分頁。菜譜超過 60 道時，以手機量測結果重新評估。

## User Stories

### 讀者：篩選

1. As a 讀者, I want 在首頁清單選「蔬菜菜」, so that 我想吃青菜時只看以蔬菜為主角的菜。
2. As a 讀者, I want 在首頁清單選「蛋白質菜」, so that 我想吃肉、魚、蛋或豆腐時能直接找到。
3. As a 讀者, I want 在首頁清單選「主食」, so that 我想吃一盤麵或飯就能吃飽時，找得到炒麵、炒飯、義大利麵和湯麵。
4. As a 讀者, I want 在首頁清單選「湯」, so that 我能只看湯品。
5. As a 讀者, I want 選「全部」回到完整清單, so that 我能隨時取消篩選。
6. As a 讀者, I want 番茄炒蛋這類同時以蔬菜和蛋為主角的菜，在蔬菜菜和蛋白質菜下都找得到, so that 我不用猜它被歸在哪一類。
7. As a 讀者, I want 湯麵出現在「主食」而不是「湯」, so that 篩選結果符合我把湯麵當成一餐的習慣。
8. As a 讀者, I want 篩選列不出現沒有任何菜的選項, so that 我不會點到一個空清單而以為網站壞了。
9. As a 讀者, I want 篩選列一次只選一個選項，目前選中的那個有清楚標示, so that 我知道清單現在顯示的是什麼。
10. As a 讀者, I want 篩選和搜尋可以並用，例如在「主食」下搜尋「牛肉」, so that 我能縮小範圍。
11. As a 讀者, I want 篩選後搜尋框下方的筆數跟著更新, so that 我知道符合條件的有幾道。
12. As a 讀者, I want 篩選後沒有結果時看到說明和「清除條件」按鈕, so that 我能一鍵回到完整清單。
13. As a 讀者, I want 篩選狀態寫在網址裡, so that 我能分享「主食」清單的連結給朋友，或重新整理後仍停在同一個篩選。
14. As a 讀者, I want 打開帶有無法辨識篩選值的網址時看到完整清單, so that 舊連結或打錯的連結不會讓頁面壞掉。
15. As a 讀者, I want 用鍵盤就能切換篩選選項，且每個選項的觸控目標夠大, so that 不用滑鼠或在手機上都好按。
16. As a 讀者, I want 清單每列的分類標籤顯示「非湯料理」「主食」或「湯」, so that 不用點進去就知道是哪一類。
17. As a 讀者, I want 菜譜頁也顯示這道菜的分類, so that 主食的菜譜頁不會被標成非湯料理。

### 讀者：手機版

18. As a 手機讀者, I want 打開首頁時第一個畫面就看得到篩選列, so that 我不用先捲動就知道可以篩選。
19. As a 手機讀者, I want 清單每列只顯示 1 行摘要, so that 一個畫面能看到大約兩倍的菜。
20. As a 手機讀者, I want 摘要被截斷時仍看得出是截斷的（省略號）, so that 我知道點進去還有更多內容。
21. As a 手機讀者, I want 捲到清單中段時篩選列仍固定在畫面頂部, so that 我不用捲回頂端就能換篩選。
22. As a 手機讀者, I want 固定在頂部的篩選列不會遮住清單第一列, so that 我切換篩選後看得到第一筆結果。
23. As a 手機讀者, I want 首頁成品大圖仍然存在，只是比較扁, so that 首頁保有一道菜的門面，又不會把清單擠到太下面。
24. As a 手機讀者, I want 輸入搜尋字詞時大圖照舊收起, so that 搜尋結果緊接在搜尋框下方。
25. As a 寬螢幕讀者, I want 首頁版面維持現狀（左文右圖、每列含摘要）, so that 手機版的調整不影響桌機體驗。
26. As a 讀者, I want 首頁在 360、390、430 寬度都沒有水平捲動, so that 新增的篩選選項不會撐破版面。

### 讀者：配一桌

27. As a 讀者, I want 配一桌不會把炒麵或義大利麵抽成四菜之一, so that 組出來的仍是配白飯吃的一桌菜。
28. As a 讀者, I want 配一桌的菜色標籤（蔬菜／蛋白質）維持原樣, so that 主食分類不影響現有的配菜體驗。

### 站主：內容製作

29. As a 站主, I want 菜譜分類可以填「主食」, so that 我新增的炒麵、義大利麵、湯麵有正確的歸屬。
30. As a 站主, I want 主食被標成配菜候選時建置失敗並指出欄位, so that 我不會意外讓主食進入配一桌。
31. As a 站主, I want 非湯料理沒標蔬菜菜也沒標蛋白質菜時建置失敗並指出欄位, so that 每道非湯料理都能在篩選中被找到。
32. As a 站主, I want 主食或湯標了蔬菜菜或蛋白質菜時建置失敗, so that 這兩個標記只用在非湯料理上，符合詞彙定義。
33. As a 站主, I want 這些規則同時套用在草稿上, so that 草稿在送審前就已經被擋下，而不是合入時才發現。
34. As a 站主, I want `recipe-making` 和 `recipe-writing` skill 說明主食的判定方式與上述規則, so that AI 製作新菜譜時一次就選對分類和標記。
35. As a 站主, I want 部署前的候選池門檻計數不包含主食, so that 門檻仍然只反映配一桌真正可用的菜。
36. As a 站主, I want 現有 19 道菜譜不需要任何修改就能通過新規則, so that 這次改動不必回頭補內容。

## Implementation Decisions

### 菜譜分類與 schema

- 分類列舉擴充為三個值：「非湯料理」「主食」「湯」，沿用現有的中文字串列舉。
- schema 新增三條規則，對草稿和已發布菜譜一律適用，各附欄位路徑與中文訊息：非湯料理的 `vegetable`、`protein` 至少一個為真；主食和湯的 `vegetable`、`protein` 必須都是假；主食的 `mealCandidate` 必須是假。
- 這三條規則放在 schema 裡，所以內容集合建置和 `pnpm check:content`（共用同一份 schema）都會擋下。不另外在內容檢查加重複的規則。
- 已核實現有 19 道菜譜：15 道非湯料理都至少帶一個標記，4 道湯都沒有標記，沒有主食，所以不需要遷移資料。

### 篩選模型（首頁工具模組）

- 「分類篩選」改成「瀏覽篩選」，值為 `all | vegetable | protein | staple | soup`。網址參數從 `category` 改名為 `kind`；`all` 不寫進網址；無法辨識的值一律視為 `all`。舊的 `category` 參數不保留相容（依 coding-style：不留相容層）。
- 新增純函式「菜譜 → 它屬於哪些篩選值」：非湯料理依標記回傳 `vegetable`、`protein` 或兩者；主食回傳 `staple`；湯回傳 `soup`。一道菜可以屬於多個值。
- 新增純函式「已發布菜譜集合 → 要顯示的篩選選項」：固定順序為 全部、蔬菜菜、蛋白質菜、主食、湯；只保留至少有一道菜的選項，「全部」一律顯示。在建置時計算。
- 網址帶有一個目前被隱藏的選項（例如還沒有主食時的 `kind=staple`）時，視為 `all`。
- 原有的「篩選值 ↔ 分類」一對一對應函式改為上述多值函式，舊函式移除。

### 搜尋整合（Pagefind）

- 菜譜頁的 Pagefind 篩選屬性改成 `kind`，每個篩選值各輸出一個屬性，讓一道菜在 Pagefind 中帶多個 `kind` 值。搜尋時以單一值過濾，命中任何一個即符合。
- 菜譜頁和清單列顯示的分類文字直接用分類值（非湯料理／主食／湯）。

### 配一桌

- 候選池只納入分類為非湯料理（菜位）和湯（湯位）的菜，主食一律排除。這是候選池層的防線，不依賴 schema 已經擋下 `mealCandidate`。
- 部署前候選池門檻沿用同一套候選池規則計數，主食自然不計入。

### 首頁版面（只限手機寬度，`< 40rem`）

- 清單列的摘要截成 1 行，結尾用省略號。完整摘要仍保留在 DOM 中，供螢幕閱讀器與 Pagefind 讀取。
- 篩選列（`.list-tools`）在手機寬度設為 sticky，固定在頂部，要有底色和下框線以免和清單重疊，也不能遮住切換後的第一列。實作時改成用腳本量測篩選列的實際底端，再把清單捲到那裡，而不是固定的 scroll margin，因為 360 寬時篩選列會折成兩行，高度不固定（見 ticket 04 的審查）。搜尋框不固定。
- 首屏調整：主內容上方空白從 48px 改為 24px；intro 到清單的間距從 64+32px 收為合計 32px；成品大圖改成 2:1（裁切置中，依圖片風格規格，主體不會貼邊）。估計篩選列頂端會落在約 716px，在 844px 的畫面內。這是推論值，驗收時以實測為準。
- 寬螢幕（`≥ 40rem`）的列版面，以及 `≥ 64rem` 的左文右圖首屏都不變。

### 詞彙與文件

- `GLOSSARY.md` 已在 grill 時更新：新增「非湯料理」與「主食」，修改菜色、湯（湯麵歸為主食）、配菜候選、蔬菜菜、蛋白質菜的定義。
- `recipe-making`、`recipe-writing` skill 補上主食的判定方式、三條 schema 規則，以及「主食不可為配菜候選」。
- `06-homepage-direction` 中「每列有……非湯料理／湯標籤，並提供『全部／非湯料理／湯』分類切換」一句已被本規格取代，在原文旁加一行註記並連結到本規格。

## Testing Decisions

### 好測試的標準

只測外部行為：讀者在頁面上看到什麼、網址變成什麼、建置或檢查是否擋下哪一筆資料。不斷言 CSS 類別名稱、內部函式呼叫次數或 DOM 結構細節。版面測試以量到的位置與尺寸斷言，不比對截圖。

### 測試縫（沿用既有四個，不新增）

1. **建置後網站（Playwright，固定菜譜）**：承載大部分行為。固定菜譜新增一道已發布的主食（帶 `mealCandidate: false`）。測試項目：五個選項各自只回對應的菜；兩種性質都有的菜同時出現在蔬菜菜和蛋白質菜下；`kind` 網址參數的寫入與還原；無法辨識的值顯示全部；篩選與搜尋並用；零筆時清除條件；390px 寬時篩選列頂端在第一個畫面（844px）內；捲到清單中段後篩選列仍在畫面頂部；手機列的摘要只顯示 1 行；360、390、430 寬度沒有水平捲動，觸控目標尺寸達標；axe-core 檢查通過；配一桌不會抽中主食。既有 `search.spec.ts` 中對 `category` 參數與「非湯料理／湯」切換的斷言，改寫成新的篩選模型。
2. **首頁工具函式（`tests/home.test.ts`）**：`kind` 參數的解析與寫回（預設值不寫入、其他參數保留）；每種分類與標記組合對應的篩選值；選項顯示規則，包括「沒有主食時不顯示主食」和「全部一律顯示」。Playwright 的固定菜譜裡有主食，測不到隱藏的情況，所以這一項放在單元層。
3. **菜譜 schema（`tests/recipe-schema.test.ts`）**：三條新規則各有通過和失敗的案例，草稿也適用，並檢查錯誤的欄位路徑。
4. **配一桌引擎（`tests/meal-planner.test.ts`）**：即使主食被標成 `mealCandidate`，候選池也排除它；候選池門檻計數不含主食。

### 前例

- 網址狀態與篩選：`tests/home.test.ts`、`e2e/search.spec.ts`（現有分類篩選與網址還原的測試）。
- schema 規則：`tests/recipe-schema.test.ts` 中已發布菜譜必須圖片齊全的 superRefine 案例。
- 手機寬度、無水平捲動、觸控目標：`e2e/a11y.spec.ts` 與 `e2e/a11y-helpers.ts`。
- 量測首屏位置可以參考 grill 時的量測方式：390×844、DPR 3，讀 `getBoundingClientRect`。

## Out of Scope

- 分頁、「載入更多」、無限捲動。菜譜超過 60 道時以手機量測結果重新評估。
- 烹調時間篩選與標籤篩選。`timeMinutes` 目前只有 1 道填寫，`tags` 有 17 道只寫了「家常菜」，資料不足以篩選。另開一張票：新增菜譜時 `timeMinutes` 必填，並補齊舊資料。
- 多選或組合篩選（例如蔬菜菜「且」主食）。
- 另開 `/recipes/` 列表頁；清單留在首頁。
- 手機頁首（全站共用，97px）壓縮。
- 主食參與的組合模式（例如「一麵兩菜一湯」）。
- 新增任何主食菜譜內容本身：本規格只交付分類、規則與介面；主食菜譜依 `recipe-making` 流程另行製作。
