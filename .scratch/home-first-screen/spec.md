# 手機首屏露出第一列菜譜規格

Type: spec
Status: open
Label: ready-for-agent

本規格整理自 2026-10-08 的 grill-with-docs 討論，接在〈首頁菜譜清單「顯示更多」規格〉（`.scratch/recipe-show-more/spec.md`）之後；當時把首屏空白列為另案。首頁大圖的隨機挑選受 ADR 0005 保護，本規格不改。

## Problem Statement

手機讀者（390×844）打開首頁，第一個畫面看得到品牌、搜尋、「這個時節」、篩選列與首頁大圖，但菜譜清單的第一列從 774px 才開始，只露出最上面一小截。篩選列（460px）到第一列之間約 314px，幾乎都是首頁大圖與「菜譜清單」標題：大圖在手機上是 2.25:1、裁切置中，約 152px 高；標題約 50px。讀者要先往下捲才看得出「這裡有一份菜譜清單」。

## Solution

在 390×844 的手機畫面上，讓第一列菜譜完整出現在第一個畫面內。做法是在手機版把首頁大圖改扁、改成完整縮放（畫不被裁切，左右露出米白底），並把「菜譜清單」標題改為只在視覺上隱藏。品牌區、「這個時節」與篩選列不動，寬螢幕版面不變，首頁大圖每次開啟隨機挑一道的行為也不變。

## User Stories

1. As a 手機讀者, I want 第一個畫面就看到完整的第一道菜譜列, so that 我一打開就知道這是一份可以瀏覽的清單。
2. As a 手機讀者, I want 首頁大圖仍然在, so that 我還是能「隨機看看一道菜」。
3. As a 手機讀者, I want 首頁大圖完整呈現整道菜、不被切掉鍋緣或盤緣, so that 插畫看起來是完整的。
4. As a 手機讀者, I want 首頁大圖每次打開仍隨機換一道, so that 推薦保有新鮮感。
5. As a 手機讀者, I want 點首頁大圖仍進入那道菜譜, so that 大圖仍是入口。
6. As a 手機讀者, I want 篩選列仍在首頁大圖之上並且捲動時固定在頂部, so that 篩選的操作方式不變。
7. As a 手機讀者, I want 篩選或搜尋時首頁大圖照舊收起, so that 結果清單一樣貼近篩選列。
8. As a 手機讀者, I want 品牌標題、直排標語與日期維持原樣, so that 網站的樣貌不變。
9. As a 手機讀者, I want 「這個時節」區塊維持原樣, so that 時令專題與節氣仍在首屏。
10. As a 螢幕閱讀器使用者, I want 清單區塊仍以「菜譜清單」為名稱, so that 我能用地標或標題跳到清單。
11. As a 螢幕閱讀器使用者, I want 「菜譜清單」標題仍在標題階層中, so that 標題導覽不缺一層。
12. As a 寬螢幕讀者, I want 首頁版面與現在相同, so that 改動只影響手機。
13. As a 小手機讀者（如 375×667）, I want 首屏不比現在擠, so that 改動不會讓小螢幕變差。
14. As a 手機讀者, I want 頁面載入時版面不跳動, so that 首頁大圖改尺寸不帶來版面位移。
15. As a 站主, I want `pnpm measure:mobile` 報告第一列底端位置, so that 我能用數字確認第一列是否完整露出。
16. As a 站主, I want 首屏被撐高時有測試失敗, so that 日後加東西到首屏時不會默默把清單推出畫面。
17. As a 站主, I want 首頁大圖比例只在一處設定, so that 日後依量測調整不必改多處。

## Implementation Decisions

- **驗收尺寸**：只以 390×844（`measure:mobile` 預設）為準：第一列底端不超過 844px。小手機只要求不比現在差，不設列數目標。
- **首頁大圖（只限手機版斷點）**：比例由 2.25:1 改為更扁，起點 3:1；改為完整縮放（contain、置中），框內空白以頁面米白底填滿，與插畫背景相融。若正式內容實測第一列仍未完整露出，再把比例調扁（例如 3.5:1），以量測結果決定，比例只定義一處。寬螢幕版面的大圖不動。
- **大圖的其他行為不變**：隨機挑選腳本、篩選時換同類大圖、搜尋或篩選中在手機收起、`fetchpriority`、建置時注入的 LCP 預載都維持；若大圖在手機的實際顯示寬度不變，`sizes` 不需調整，改變則同步更新。
- **「菜譜清單」標題**：手機版斷點下改為視覺隱藏（仍在 DOM、仍是 `h2`、清單區塊的 `aria-labelledby` 不變）；寬螢幕照舊顯示。專案若沒有視覺隱藏的共用樣式，就在首頁就地定義，不為此新增全站工具類別。
- **不動**：品牌區（日期、標題、直排標語）、「這個時節」、搜尋區、篩選列的位置與固定行為。
- **量測腳本**：`measure:mobile` 新增第一列底端欄位（第一列頂端加列高），與既有的第一列頂端並列。
- **用詞**：沿用 ADR 0005 的「首頁大圖」；畫面上的標籤「隨機看看一道菜」不變。

## Testing Decisions

- 好的測試只驗證讀者看得到的結果：元素在視窗中的位置、可存取名稱；不檢查 CSS 屬性值。
- **e2e（預設站台，沿用既有手機版規格）**：既有的 390×844 首屏測試目前只斷言第一道菜名在首屏內，改為斷言整個第一列的底端不超過 844，並保留「搜尋 → 篩選列 → 首頁大圖 → 第一列」的順序斷言。新增：手機上「菜譜清單」標題不可見，但清單區塊的可存取名稱仍是「菜譜清單」、標題仍在標題階層中；寬螢幕 1366 時標題可見。既有「寬螢幕 1366 版面不變」測試照舊通過。前例是現有的手機版清單規格（固定日期讓「這個時節」整區顯示）。
- **量測**：以正式內容 `pnpm build && pnpm measure:mobile` 實測，第一列底端不超過 844，數字貼在 PR 說明。固定菜譜與正式內容的首屏高度若有差異，以正式內容量測為準。

## Out of Scope

- 品牌區與直排標語的調整。
- 「這個時節」區塊、搜尋區、篩選列的調整。
- 寬螢幕版面。
- 改變首頁大圖的隨機挑選方式（ADR 0005）。
- 以小手機（375×667 等）為目標的列數要求。

## Further Notes

- 量測依據：2026-10-08 以正式內容在 390×844 量得篩選列頂端 460px、第一列頂端 774px、列高 142px（第一列底端 916px，需收回約 72px）。估算：大圖 2.25:1 → 3:1 約省 38px，標題約省 50px，合計約 88px，餘裕約 16px；各區高度由截圖估計，以實測為準。
