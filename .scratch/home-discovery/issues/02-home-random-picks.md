# 02: 首頁隨機推薦（第一批）

**What to build:** 讀者開啟首頁時，篩選區與「菜譜清單」標題之間出現隨機推薦區塊（標題暫定「今天煮什麼」），每次開啟頁面都在瀏覽器端隨機抽 6 道已發布、有成品圖的菜譜，排除當次大圖那道，卡片沿用票 01 的元件。選了料理主角篩選時只從該類抽，切換篩選立即重抽；有搜尋字時區塊隱藏，清除後再出現；候選不足 6 道時全部顯示，0 道時整個區塊隱藏；沒有 JavaScript 時不顯示。桌機一列 6 張，手機（< 40rem）一列橫向捲動。這張不含「換一批」按鈕。規格見 `.scratch/home-discovery/spec.md`〈隨機推薦模組〉；不改 ADR 0005 的大圖行為。

**Blocked by:** 01（共用卡片元件）

**Status:** ready-for-agent

- [ ] 抽批是純函式：輸入候選識別值、這一輪已出現過的識別值、亂數來源，輸出最多 6 個識別值與更新後的已出現集合；不讀 DOM、不呼叫全域亂數；候選 ≤ 6 時回傳全部；同一批內不重複；不改動輸入
- [ ] 單元測試以固定的亂數序列涵蓋上述行為
- [ ] 候選的分類判斷與大圖、清單篩選共用現有的分類函式
- [ ] 候選資料在建置時寫進頁面，未被抽中的卡片圖片不下載；卡片圖片延遲載入，不搶大圖的 `fetchpriority`
- [ ] 不寫入 history state、localStorage、sessionStorage；顯示更多的返回位置還原照舊
- [ ] e2e（覆寫 `Math.random`，沿用大圖測試的做法）：張數正確且不含大圖那道（固定菜譜扣掉大圖剩 5 道，驗證不足一批時全部顯示）、篩選後只剩該類、有搜尋字時隱藏、清除後再出現、停用 JavaScript 時不顯示
- [ ] `e2e/mobile-list.spec.ts`、`e2e/a11y.spec.ts` 維持全綠
- [ ] 用正式內容建置後跑 `pnpm measure:mobile`，在 PR 說明回報加入區塊前後，第一列清單位置與一屏列數的差異，交由站主決定是否接受
- [ ] `pnpm check && pnpm test && pnpm test:e2e` 通過
