# 菜譜、菜色與圖片的內容契約

Type: grilling
Status: resolved
Assignee: Carl
Blocked by: 01

## Question

如何定義「菜譜」「菜色」「湯」與配菜候選項？每份結構化菜譜應有哪些必要欄位、分類、材料份量、步驟、圖片及圖片替代文字；材料圖和步驟圖的數量關係為何；草稿與正式發布需要哪些驗證？

## Answer

### 內容模型

- 一份菜譜描述一道成品料理，也對應一道菜色。菜譜可收錄多國料理，如義大利麵；MVP 的必要分類是「非湯料理」與「湯」，不以中式料理為界。分類依上桌用途：以喝湯為目的的料理是湯；火鍋、燉菜和醬汁料理屬非湯料理，其配菜資格另行標記。
- 配菜候選是已發布且由站主明確標記可參與「四菜一湯／五菜一湯」的菜色；未標記的公開菜譜仍可收藏與搜尋。候選資格預設為否，抽選只使用候選項。首批上線時，候選池至少有 12 道非湯料理與 3 道湯；更細的搭配條件由配菜規則票決定。
- 候選菜譜另有受控平衡標記「蔬菜菜」「蛋白質菜」，可同時具有兩者，也可皆無。蔬菜菜須以蔬菜為主角；蛋白質菜以魚、肉、蛋、豆腐或豆類為主要食材。套餐須由不同的兩道菜分別滿足兩項最低要求。
- 每份菜譜有穩定、唯一的識別值，供頁面路徑與內部來源紀錄對應。時間、難度、料理風格、其他受控標籤及少量搜尋別名可選；料理風格可包含臺式、義式等，不限制菜譜收錄地域。

### 公開菜譜必備內容

- 標題、摘要、正整數份數、非湯料理／湯分類。
- 至少一項結構化材料：名稱、用量及可選備註。主要材料的用量由數值與適當單位組成；重量、液量以公制為主，雞蛋、大蒜等可用顆、瓣等計數單位。調味品可改用「適量」，此時沒有數值及單位。材料可附個別圖片，但不強制。
- 至少一步按順序排列的文字做法；每一步可附圖片。整份菜譜至少有一張與某一步對應的關鍵步驟圖。
- 成品圖與材料合照各至少一張。每張公開圖片（含個別材料圖及步驟圖）都要有描述性的替代文字。所有料理圖片使用[首頁視覺方向票](06-homepage-direction.md)〈圖片風格規格〉定義的手繪水彩插畫。
- 至少一個經站主核准的公開來源網址，留在儲存庫的內部來源紀錄，不輸出到網站頁面或其他網站產物；儲存庫公開，來源紀錄本身可在 GitHub 上看到。AI 重新表述文字並在本地製圖，不搬用來源原文或原圖。

### 草稿與驗證邊界

- 草稿可缺部分內容或圖片，只供本地預覽，不能進入公開建置。已發布菜譜必須通過上述完整性驗證並經站主逐篇看成品後核准；不要求逐項比對來源或試做，也不宣稱未試做內容已試做。
- 來源紀錄與公開內容分開保存，以菜譜識別值對應，置於 Astro 內容載入範圍及 `public/` 之外。發布檢查須確認每份公開菜譜都有來源、無孤兒紀錄，且建置輸出不含內部來源網址。Git 審核承載人員核准紀錄；自填的核准布林值不能代替人工審閱。

站主已確認上述內容需求。來源清單的操作、審稿動作、完整的建置檢查，以及配菜演算法留給後續決策票。
