# MVP 實作規格：卡爾廚房菜譜網站

Type: spec
Status: open
Label: ready-for-agent
Blocked by: 01, 02, 03, 04, 05, 06, 07, 08

## Problem Statement

站主想要一個自己和一般家常料理讀者都能用的繁中菜譜網站：能快速找到想煮的菜、照著清楚的材料與做法下廚，沒想法時還能一鍵湊出一桌四菜一湯或五菜一湯。內容由 AI 依站主核准的公開資料在本地製作，但站主必須能確信：沒有經他逐篇審閱的菜譜不會上線，來源網址與草稿不會外洩，圖文不會互相矛盾，網站也不會把未試做的內容說成已試做。決策地圖 01–08 已定下所有產品與流程規則，但目前沒有任何程式、儲存庫或部署環境。

## Solution

建立一個 Astro 靜態網站，部署到 `carlkitchen.gravito.dev`，包含五個頁面：首頁（搜尋＋全部菜譜清單）、菜譜頁、四菜一湯／五菜一湯頁、關於頁與 404。視覺採安靜克制的日系版面，料理圖片全部是手繪水彩插畫。

菜譜以內容集合保存，站主合入主分支就是發布核准。合入前與部署前有八項自動檢查把關；候選池未達 12 道非湯料理＋3 道湯時，部署工作停止並列出缺額，因此菜譜可以在上線前逐篇累積。上線 PR 附驗收檢核表，由站主逐項勾選。

## User Stories

### 讀者：首頁與搜尋

1. As a 讀者, I want 首頁第一屏就有搜尋框, so that 我不用捲動就能開始找菜。
2. As a 讀者, I want 首頁第一屏旁邊有一道菜的成品大圖, so that 我沒有目標時也能被一道菜吸引。
3. As a 讀者, I want 成品大圖每次開啟時隨機換一道已發布菜譜, so that 每次來都有新鮮感。
4. As a 讀者, I want 點成品大圖就進入該道菜的菜譜頁, so that 看到想吃的菜能直接看做法。
5. As a 讀者, I want 首頁下方列出全部已發布菜譜, so that 我能直接瀏覽整個收藏。
6. As a 讀者, I want 每列菜譜顯示成品縮圖、菜名、摘要和非湯料理／湯標籤, so that 我不用點進去就能判斷要不要看。
7. As a 讀者, I want 在搜尋框輸入時清單立即篩選, so that 我不用按搜尋鍵也能看到結果。
8. As a 讀者, I want 搜尋框下方提示符合幾道, so that 我知道結果在下方以及有多少。
9. As a 讀者, I want 依菜名、材料名稱、受控標籤或別名搜尋, so that 我用「番茄」「蕃茄」或「雞蛋」都找得到相關菜譜。
10. As a 讀者, I want 只出現在步驟、用量或圖片替代文字的詞不會命中, so that 搜尋結果不被雜訊淹沒。
11. As a 讀者, I want 有字詞時結果依相關度排序、菜名命中優先, so that 最相關的菜在最上面。
12. As a 讀者, I want 沒有字詞時清單依菜名排序, so that 我能穩定地瀏覽全部菜譜。
13. As a 讀者, I want 切換「全部／非湯料理／湯」, so that 我只看想要的類別。
14. As a 讀者, I want 分類篩選在有無字詞時都生效, so that 我能找「湯」裡的「雞」。
15. As a 讀者, I want 查無結果時看到明確的零筆訊息和清除條件按鈕, so that 我知道下一步怎麼做。
16. As a 讀者, I want 搜尋字詞與分類寫進網址, so that 我能把搜尋結果分享給別人，重新整理也不會消失。
17. As a 讀者, I want 開啟帶有搜尋參數的連結時還原同樣的結果, so that 別人分享的連結能直接用。
18. As a 手機讀者, I want 第一屏先看到搜尋框，下面接成品大圖和清單, so that 我在手機上也能先搜尋。
19. As a 手機讀者, I want 輸入搜尋字詞時大圖收起, so that 結果緊接在搜尋框下方。
20. As a 讀者, I want 導覽列的「菜譜」帶我到首頁清單, so that 我隨時能回到全部菜譜。

### 讀者：菜譜頁

21. As a 讀者, I want 菜譜頁顯示菜名、摘要、份數、時間與分類, so that 我先知道這道菜的基本資訊。
22. As a 讀者, I want 看到成品插畫, so that 我知道做出來大概的樣子。
23. As a 讀者, I want 材料清單分成主料與調味，並有材料合照, so that 我能對照備料。
24. As a 讀者, I want 用量是公制或顆、瓣、支，調味料可寫「適量」, so that 我照份量就能做。
25. As a 讀者, I want 做法依序編號、每步寫出熟度訊號, so that 我知道什麼時候進下一步。
26. As a 讀者, I want 關鍵步驟附步驟插畫, so that 我能看懂文字難描述的狀態。
27. As a 讀者, I want 寬螢幕上捲動做法時材料清單保持可見, so that 我不用來回捲動。
28. As a 讀者, I want 列印菜譜時只留材料、做法與成品圖, so that 我能帶一張紙進廚房。
29. As a 讀者, I want 每張料理圖旁標示「AI 繪製插畫」, so that 我知道圖不是實拍。（已由 [ADR-0001](../../../docs/adr/0001-drop-illustration-caption.md) 取消）
30. As a 讀者, I want 頁底看到「依公開資料由 AI 整理、站主審閱，未經試做」, so that 我知道內容的可信程度。
31. As a 讀者, I want 菜譜頁不顯示任何來源連結, so that 內容保持乾淨（也符合來源保密）。
32. As a 視障讀者, I want 每張圖都有描述畫面內容的替代文字, so that 我能理解圖片傳達的資訊。

### 讀者：四菜一湯／五菜一湯

33. As a 讀者, I want 一鍵抽出四菜一湯, so that 我不用自己想今晚煮什麼。
34. As a 讀者, I want 切換成五菜一湯, so that 人多時也能用。
35. As a 讀者, I want 套餐只從配菜候選中抽選, so that 抽到的都是適合搭配的菜。
36. As a 讀者, I want 同一組菜不重複, so that 套餐有變化。
37. As a 讀者, I want 每組至少有一道蔬菜菜和另一道蛋白質菜, so that 套餐營養均衡。
38. As a 讀者, I want 同時有兩種標記的混合料理不能獨自滿足兩項要求, so that 「均衡」是真的兩道不同的菜。
39. As a 讀者, I want 鎖定想保留的菜（包括湯）, so that 重新抽選時它們留下來。
40. As a 讀者, I want 重新抽選時未鎖定的位置盡量換成與上一組不同的菜, so that 每次重抽都有新組合。
41. As a 讀者, I want 只替換其中一道未鎖定的菜, so that 我不滿意一道時不用整組重來。
42. As a 讀者, I want 替換時保持菜／湯類別、不重複與蔬菜／蛋白質平衡, so that 替換後的套餐仍然合規。
43. As a 讀者, I want 想替換已鎖定的菜時被提示先解鎖, so that 我理解為何不能替換。
44. As a 讀者, I want 找不到替代菜時原套餐不變並看到原因, so that 我不會得到違規或殘缺的套餐。
45. As a 讀者, I want 從五菜切回四菜但鎖了超過四道非湯菜時，保持原狀並提示先解鎖, so that 我的鎖定不會被暗中丟掉。
46. As a 讀者, I want 候選池不足以組出合規套餐時看到明確說明, so that 我知道不是網站壞了。
47. As a 讀者, I want 重新整理頁面後套餐、模式與鎖定仍在, so that 誤按重整不會失去結果。
48. As a 讀者, I want 關閉分頁後重新開始, so that 每次新造訪都是新的一桌。
49. As a 讀者, I want 保存的套餐中有菜譜已下架時，失效套餐被清除並請我重抽, so that 我不會點到不存在的菜。
50. As a 讀者, I want 套餐中的每道菜都能點進菜譜頁, so that 我能直接看做法。

### 讀者：其他頁面與通用體驗

51. As a 讀者, I want 關於頁說明內容來源、AI 製作與站主審閱流程, so that 我理解這個網站的內容怎麼來。
52. As a 讀者, I want 不存在的網址顯示 404 並引導回首頁, so that 我不會卡住。
53. As a 鍵盤使用者, I want 只用鍵盤就能搜尋、篩選、鎖定、替換與重抽, so that 我不需要滑鼠。
54. As a 鍵盤使用者, I want 焦點位置清楚可見, so that 我知道目前在哪個元件上。
55. As a 手機讀者, I want 任何頁面都沒有水平捲動, so that 閱讀不卡頓。
56. As a 手機讀者, I want 分類切換與鎖定／替換按鈕至少 44×44 px, so that 我不會誤觸。
57. As a 手機讀者, I want 首頁首次載入夠快, so that 在行動網路下也能順利使用。

### 站主：內容製作與審閱

58. As a 站主, I want 只有我核准的來源能被用來製作菜譜, so that 內容依據可控。
59. As a 站主, I want 每份菜譜的來源網址記在儲存庫內的內部來源紀錄、不輸出到網站, so that 我能追溯，網站讀者看不到來源。
60. As a 站主, I want AI 依專案寫作規範重述菜譜文字, so that 每份菜譜語氣、用語、單位一致且不抄原文。
61. As a 站主, I want AI 依圖片風格規格製作整組插畫並轉成 WebP, so that 全站圖片一致且檔案小。
62. As a 站主, I want AI 為分類、配菜候選與蔬菜／蛋白質標記附理由提議, so that 我審稿時能快速決定。
63. As a 站主, I want 草稿只能在本地預覽、不進正式建置, so that 未完成內容不會上線。
64. As a 站主, I want 用本地預覽審閱每份菜譜的頁面與差異, so that 我看過成品才核准。
65. As a 站主, I want 合入 PR 就等於發布核准, so that 核准紀錄留在 Git 而不是自填欄位。
66. As a 站主, I want 菜譜可以在上線前逐篇合入, so that 我不必一次審 15 篇。

### 站主：品質門檻與部署

67. As a 站主, I want 缺必填欄位、分類或標記錯誤時 PR 無法合入, so that 結構錯誤的菜譜上不了線。
68. As a 站主, I want 公開菜譜沒有來源紀錄、或有孤兒來源紀錄時 PR 無法合入, so that 每份內容都可追溯。
69. As a 站主, I want 建置輸出含草稿或內部來源網址時 PR 無法合入, so that 網站不會出現未發布內容或來源。
70. As a 站主, I want 圖片不是 WebP、尺寸不對、超過 300 KB、缺替代文字或缺必要圖片時 PR 無法合入, so that 圖片品質與效能有底線。
71. As a 站主, I want 搜尋以真實內容產生的斷言驗證, so that 新增菜譜後搜尋仍可靠，不必手寫預期結果。
72. As a 站主, I want 配菜四個情境在每個 PR 都被驗證, so that 規則不會被改壞。
73. As a 站主, I want 無障礙與多寬度版面自動檢查, so that 退步會在合入前被抓到。
74. As a 站主, I want 部署設定錯誤在 PR 階段就被 dry-run 抓到, so that 合入後不會部署失敗。
75. As a 站主, I want 合入主分支後自動部署到正式網址, so that 主分支和正式站一致。
76. As a 站主, I want 候選池未達 12＋3 時部署停止並列出缺額, so that 不會上線一個配菜功能不可用的網站。
77. As a 站主, I want 首次達標後每次部署都維持門檻, so that 下架菜譜不會讓配菜壞掉。
78. As a 站主, I want 出問題時用 `git revert` 回滾並自動重新部署, so that 回滾後主分支仍等於正式站。
79. As a 站主, I want CI 故障時有緊急回滾程序, so that 正式站不會長時間停在壞版本。
80. As a 站主, I want 網站只在正式網址提供、沒有 workers.dev 或預覽網址, so that 沒有第二個公開入口。
81. As a 站主, I want 上線 PR 附驗收檢核表讓我逐項勾選, so that 上線驗收有紀錄。

### 站主：儲存庫與權限

82. As a 站主, I want 草稿只留在本地、準備送審時才推送, so that 公開儲存庫上不會出現半成品。
83. As a 站主, I want 主分支受分支保護（必經 PR、必要檢查通過、禁止強制推送與刪除）, so that 只有通過檢查的變更能進主分支。
84. As a 站主, I want 代理只能推送工作分支與開 PR、不能合入, so that 只有我能發布。
85. As a 站主, I want README 記錄指令與回滾程序, so that 日後接手的人知道怎麼操作。

## Implementation Decisions

### 技術基線

- 沿用 CarlStack 的技術組合：Astro（靜態輸出）＋TypeScript、內容集合、建置後執行 Pagefind、GitHub Actions、Cloudflare Workers Static Assets、pnpm、Node 內建測試執行器。不沿用 CarlStack 的視覺風格或其部落格專用功能。
- 網站全站語言為 `zh-Hant`；Pagefind 依頁面語言建立索引。
- 執行期沒有後台、資料庫、登入或 AI 呼叫；首頁隨機大圖與配菜抽選都在瀏覽器端執行。

### 模組

1. **菜譜內容模型**：內容集合的 schema，對應內容契約（02）：穩定唯一識別值、標題、摘要、正整數份數、分類（非湯料理／湯）、草稿旗標、材料（名稱、可選數值與單位、可選備註、分組；「適量」時無數值與單位）、依序做法（每步文字與可選步驟圖）、成品圖、材料合照、每張圖的替代文字、配菜候選（預設否）、蔬菜菜／蛋白質菜標記、可選的時間、難度、料理風格、受控標籤與搜尋別名、可選小提醒。草稿在開發模式可見，正式建置一律排除（頁面、清單、索引、sitemap）。
2. **內部來源紀錄**：與公開內容分開保存，位於內容載入範圍與公開資產目錄之外，以菜譜識別值對應，每筆至少一個核准來源網址。不被任何頁面或建置產物讀取。
3. **配菜引擎（深模組，獨立測試縫）**：純函式介面，輸入候選池（每道菜的識別值、類別、蔬菜／蛋白質標記）、目前套餐狀態與一個動作，輸出新狀態，或附原因的無解結果而狀態不變。內部負責組合列舉、平衡判定（兩項要求由不同菜色滿足）、與上一組差異最大化、鎖定保留與模式切換規則。隨機性由注入的種子決定，測試可重現。下列狀態與動作形狀來自配菜規則原型（05），是已驗證的決策：

   ```ts
   // 取自 meal-planner 原型，精簡為決策相關部分
   type Slot = { id: string; locked: boolean };
   type Plan = { mode: 4 | 5; dishes: Slot[]; soup: Slot | null; seed: number };
   type Action =
     | { type: "reroll" }
     | { type: "mode"; mode: 4 | 5 }
     | { type: "replace"; target: number | "soup" }
     | { type: "toggle"; target: number | "soup" };
   type Result = { ok: true; plan: Plan; message: string }
               | { ok: false; plan: Plan; reason: string }; // 無解時 plan 為原狀
   ```

   - 規則：非湯菜互不重複；只抽配菜候選；至少一道蔬菜菜與**另一道**蛋白質菜；重抽保留鎖定項、未鎖定位置盡量與上一組不同；替換排除目前已選且維持平衡；鎖定項須先解鎖才能替換；五切四時鎖定的非湯菜多於四道則無解；候選不足時不產生不完整或重複套餐。
4. **配菜頁 UI**：薄外殼，呼叫配菜引擎並呈現結果與訊息；套餐、模式與鎖定存在同一分頁的 session 儲存。載入時驗證保存的菜譜識別值仍在目前候選池中，否則清除並提示重抽。
5. **首頁**：I＋J 版面（06）。第一屏：日期、標題、搜尋框、符合筆數提示、「配一桌四菜一湯」入口與隨機成品大圖；下方：全部菜譜清單與分類切換。清單與無字詞排序由建置時的公開菜譜資料產生；有字詞時呼叫 Pagefind。搜尋字詞與分類同步到首頁網址並可還原。手機搜尋中收起大圖。
6. **搜尋索引範圍**：以 Pagefind 的索引範圍標記只收錄菜譜頁中可搜尋的區塊（標題、摘要、材料名稱、受控標籤、別名）；步驟、用量、圖片替代文字與首頁、關於頁等非菜譜頁不進索引。分類以 Pagefind 篩選屬性提供；標題提高權重。明確控制 metadata，避免圖片替代文字被自動收錄為可搜尋內容。結果卡所需的縮圖與替代文字從建置時的公開菜譜清單取得。
7. **菜譜頁**：材料（寬螢幕固定在側邊）、編號做法與步驟插畫、成品插畫、每張圖的「AI 繪製插畫」標示（已由 [ADR-0001](../../../docs/adr/0001-drop-illustration-caption.md) 取消）、頁底未試做聲明、列印樣式表。
8. **關於頁與 404**。
9. **共用版面與設計語彙**：米白底 `#F7F6F3`、炭灰字、細線、明體標題配黑體內文、大量留白；插畫視為帶自身紙底的圖，不依賴去背或混色。所有互動元件有可見焦點與至少 44×44 px 觸控目標。
10. **圖片管線**：主分支只存 WebP 母檔（1536×1024、3:2、≤ 300 KB）；頁面透過 Astro 圖片元件產生響應式尺寸。PNG 原圖與提示詞是中間產物，不進主分支。
11. **內容與輸出檢查指令（測試縫）**：單一指令，讀取內容集合、內部來源紀錄與建置輸出，回傳通過／失敗與逐項問題清單。檢查：來源覆蓋與孤兒紀錄；建置輸出不含草稿頁或 slug、不含任何內部來源網址；圖片格式、尺寸、大小、替代文字與三類必要圖片齊全。另提供候選池門檻模式（非湯料理 ≥ 12、湯 ≥ 3），供部署工作使用。
12. **CI 與部署**：PR 工作流程依序執行八項必要檢查（07、08）；部署工作流程在推送主分支或手動觸發時執行，先跑同樣的檢查與候選池門檻，再部署。沒有排程。部署設定只服務自訂網域 `carlkitchen.gravito.dev`，關閉 workers.dev 與預覽網址。部署並行群組不取消進行中的部署。
13. **專案治理文件**：AGENTS.md 加入代理權限規則（草稿留在本地；送審時才推送工作分支並開 PR；不推主分支、不合入）與專案 skill 指引；README 記錄安裝、開發、建置、測試、檢查指令與回滾程序（一般 `git revert`；CI 故障時 `wrangler rollback` 再修主分支）。驗收檢核表依 08 建立。

## Testing Decisions

### 好測試的標準

- 只驗證外部行為：讀者在瀏覽器看到與能做的事、配菜引擎對輸入的輸出、檢查指令的通過／失敗與問題清單。不斷言內部函式、元件結構或 CSS 類名。
- 斷言可由資料產生時就由資料產生（例如「每道已發布菜譜的菜名都能搜到它」），不寫死會隨內容變動的預期結果。
- 隨機行為以注入種子或比較不變量（不重複、平衡、鎖定保留）驗證，不比對特定抽選結果。

### 三個測試縫

1. **建置後網站（Playwright，對 `astro build` 後的預覽伺服器）**：最高層、承載大部分行為。
   - 搜尋（門檻第 5 項）：以真實內容產生斷言——每道菜譜的菜名、第一項材料與每個別名都能查到該菜譜；菜／湯篩選只回該類；只出現在步驟、用量或替代文字的詞查不到；草稿不出現；網址參數還原；零筆與清除條件。
   - 配菜 E2E（第 6 項的瀏覽器部分）：以測試專用的固定菜譜資料建置，跑原型的四個情境（替換無解、鎖定衝突、候選不足、同分頁重整），並驗證失效套餐清除。
   - 無障礙與版面（第 8 項）：五個頁面的 axe-core 檢查；在 360、390、430、1366、1920 寬度檢查無水平捲動與觸控目標尺寸；鍵盤可完成搜尋、篩選、鎖定、替換與重抽。
2. **配菜引擎（Node 內建測試執行器）**：第 6 項的單元部分。覆蓋 05 的每一條規則與無解分支：平衡須由不同菜色滿足、鎖定保留、重抽差異、單道替換維持平衡、鎖定項不可替換、五切四鎖定過多、湯的鎖定與替換、候選不足、同種子可重現。
3. **內容與輸出檢查指令（Node 內建測試執行器＋對真實內容執行）**：第 2–4 項。指令本身以小型固定資料測試每種失敗（缺來源、孤兒紀錄、草稿外洩、來源網址外洩、圖片格式／尺寸／大小／替代文字／缺圖、候選池不足）；CI 再對真實內容與建置輸出執行。

門檻第 1 項（`astro check` 與建置，含 schema 驗證）與第 7 項（`wrangler deploy --dry-run`）直接使用工具，不另建測試縫。

### 前例

- CarlStack 的單元測試使用 Node 內建測試執行器搭配 TypeScript 型別剝除，涵蓋內容、SEO、網址等工具函式；CI 在 PR 上依序執行格式、`astro check`、建置、測試與 `wrangler deploy --dry-run`。本站沿用此骨架。
- CarlStack 沒有 Playwright、草稿外洩、來源覆蓋、圖片或無障礙檢查；這些是本站新增，沒有前例可循。
- 配菜四個情境的預期行為以配菜規則原型（05，保存在主分支的原型檔）為準。

- 第一次部署前需由站主完成的帳號操作：設定分支保護的必要檢查、在 Cloudflare 設定 `carlkitchen.gravito.dev` 自訂網域、建立部署所需的 API token 與帳號 ID 並存為儲存庫 secrets。這些需要站主的帳號權限，代理無法代為完成。
