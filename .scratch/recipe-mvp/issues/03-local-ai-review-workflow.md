# 本地 AI 製作與人工審核流程

Type: grilling
Status: resolved
Assignee: Carl
Blocked by: 02

## Question

AI 如何依站主核准的來源清單，在本地產出首頁素材、重新表述的結構化菜譜、材料圖及步驟圖？站主逐篇看成品並核准的具體動作與紀錄為何；如何避免直接搬用原文原圖、避免未核准內容進入 Git 發布，以及避免把未試做內容描述為已試做？

## Answer

### 來源與本地產製

1. 站主直接提供來源網址，或先核准 AI 提出的候選網址；AI 只從已核准來源製作菜譜。每份公開菜譜的來源對應關係記在儲存庫中的內部來源紀錄；儲存庫公開，來源紀錄在 GitHub 上可見，但不加入菜譜資料或網站輸出。
2. AI 在本地製作結構化菜譜、重新表述的文字、成品圖、材料合照、關鍵步驟圖、必要替代文字，以及首頁素材。不搬用來源原文或原圖；首頁視覺及素材的具體方向由首頁原型票決定。
3. 核准來源若缺必要份量或關鍵步驟，先補找並取得站主核准的另一來源；仍不足時保留草稿，不公開。圖與材料、步驟或成品文字不一致時，重製或修正到一致才送審。

### 人工核准與 Git 邊界

1. 未完成的草稿只留在本地工作分支，供本地預覽；準備好送站主審閱時才推送分支並開 PR，不合入主分支前不算發布；公開建置排除草稿。AI 可準備內容與差異，但只有站主能核准合入主分支。
2. 站主逐篇查看本地頁面預覽與檔案差異，至少看文字、圖片與替代文字、來源對應紀錄、配菜資格及蔬菜／蛋白質標記。站主合入主分支的動作就是發布核准紀錄；欄位中的自填核准值不能取代這個動作。
3. 主分支只保留最終菜譜、圖片、替代文字和內部來源紀錄；暫存提示詞與中間圖片不進主分支。首頁素材同樣須經本地預覽、差異檢視及站主合入。
4. 不要求逐項比對原來源或親自試做；未試做內容不可寫成已試做。主分支發布與建置門檻（完整 schema、來源覆蓋、輸出洩漏及草稿排除等）由靜態發布票定義。

站主已確認這個流程。
