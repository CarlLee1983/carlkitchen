# 菜譜搜尋範圍與結果體驗

Type: grilling
Status: resolved
Assignee: Carl
Blocked by: 02

## Question

MVP 應搜尋哪些菜譜欄位，是否需要分類、材料或其他篩選；中文查詢、空結果、草稿排除與排序如何表現？CarlStack 的 build-time Pagefind 能否符合所選體驗，需哪些最小調整？

## Answer

### 搜尋資料與排名

- 只搜尋已發布菜譜，包含未標記為配菜候選的菜譜；草稿、首頁和其他非菜譜頁不進索引。
- 關鍵字搜尋標題、摘要、材料名稱、受控標籤和可選的菜譜／材料別名；不搜尋用量數字或完整步驟。別名用於「番茄／蕃茄」等少量人工挑選的異名，不做自動同義詞、拼寫修正或簡繁轉換。
- 只提供「全部／非湯料理／湯」分類篩選。材料直接用關鍵字查；MVP 不做材料或料理風格的獨立篩選。
- 有查詢字詞時依相關度排序，標題命中優先；沒有字詞時列出全部已發布菜譜，依菜名排序。分類篩選在兩種狀態都生效。

### 互動與結果

- 輸入後短暫停頓即更新結果；關鍵字與分類同步到可分享的網址，重新載入或開啟連結會還原狀態。
- 結果卡顯示成品縮圖、菜名、摘要、非湯／湯標籤及可用的命中片段；沒有合適片段時以摘要代替。不顯示內部來源網址。
- 查無結果或篩選後為零筆時，顯示明確的零筆訊息和清除關鍵字、分類的操作；不自動放寬條件。

### 靜態實現邊界

- 沿用 CarlStack 的 `astro build` 後執行 Pagefind 的靜態索引方式，以及瀏覽器端搜尋頁形狀；只把公開菜譜頁送入索引。空白查詢的全部菜譜清單由建置時的菜譜資料產生，無須搜尋服務或資料庫。
- 以 Pagefind 的索引範圍標記限制可搜尋區塊，並明確控制可搜尋 metadata；分類標記提供篩選，標題權重維持相關度優先。Pagefind 可能自動收錄圖片替代文字等 metadata，不能只靠正文範圍標記排除未選欄位。結果卡所需的縮圖與替代文字可從建置時的公開菜譜清單取得，不必讓它們成為可搜尋 metadata。官方文件分別說明[索引範圍](https://pagefind.app/docs/indexing/)、[篩選](https://pagefind.app/docs/filtering/)與[metadata 搜尋](https://pagefind.app/docs/metadata/)；CarlStack 的現有搜尋頁與 build 指令可作為程式參照。
- [Pagefind 中文文件](https://pagefind.app/docs/multilingual/)說明中文斷詞支援，但 CarlStack 尚無中文搜尋實測。驗收時用正式建置索引檢查菜名、材料、別名與分類篩選的繁中查詢，並以僅出現在步驟、用量或圖片替代文字的詞做反向查詢；還要確認草稿和內部來源不出現在結果與索引中。
