# 首頁菜譜清單「顯示更多」規格

Type: spec
Status: open
Label: ready-for-agent

本規格整理自 2026-10-08 的 grill-with-docs 討論。詞彙見 `GLOSSARY.md`〈瀏覽〉：「顯示更多」是本功能的正式名稱，「分頁」只指瀏覽器分頁。本規格取代〈菜譜瀏覽規格〉中「這次不做分頁」的保留條件。

## Problem Statement

已發布菜譜到了 68 道，超過〈菜譜瀏覽規格〉約定的 60 道重新評估門檻。在手機（390×844）上量測，首頁清單每列 142px，一個畫面放得下 5 列，「全部」要捲約 14 個畫面才到底，頁面總高 10650px。讀者雖然在搜尋框下方看得到「共 68 道」，但捲動時沒有段落感，也看不到盡頭，想瀏覽的讀者只能一直往下滑。

各篩選目前的長度是蛋白質菜 30 道、蔬菜菜 25 道、湯 13 道、主食 9 道，都比「全部」短得多；但菜譜會持續增加，單一篩選遲早也會變長。

## Solution

首頁菜譜清單一次只顯示一批 20 列，清單底部有一顆按鈕寫著「再顯示 20 道（還有 N 道）」，讀者按一次就多顯示一批，直到全部顯示，按鈕消失。所有列在頁面一開始就已存在，按鈕只是讓隱藏的列出現，不另外載入資料，也不產生新網址。

這條規則不分「全部」、性質篩選或搜尋結果：只要目前要顯示的列超過一批，就截斷並出現按鈕。讀者切換篩選或改搜尋字詞時，回到只顯示第一批。讀者點進某道菜譜再按上一頁回來時，維持離開前已展開的數量。沒有 JavaScript 的讀者看到完整清單。

## User Stories

1. As a 手機讀者, I want 首頁清單一開始只顯示 20 道, so that 我不用面對一條看不到底的清單。
2. As a 手機讀者, I want 清單底部有「再顯示 20 道」的按鈕, so that 我知道下面還有菜，並決定要不要繼續看。
3. As a 讀者, I want 按鈕寫出還剩幾道, so that 我能判斷還要看多久。
4. As a 讀者, I want 最後一批不足 20 道時按鈕寫實際的數量, so that 按鈕文字不會誇大，例如「再顯示 8 道（還有 8 道）」。
5. As a 讀者, I want 全部顯示完後按鈕消失, so that 我知道已經到底。
6. As a 讀者, I want 清單總數不超過一批時完全看不到按鈕, so that 短清單維持原樣。
7. As a 讀者, I want 搜尋框下方仍顯示「共 N 道」, so that 截斷之後我仍知道總共有幾道。
8. As a 讀者, I want 按「蛋白質菜」等篩選後，結果超過 20 道時同樣先顯示 20 道, so that 每份清單的行為一致。
9. As a 讀者, I want 搜尋結果超過 20 筆時同樣先顯示 20 筆, so that 搜尋結果也不會一次塞滿畫面。
10. As a 讀者, I want 搜尋結果依相關度排序後才截斷, so that 最相關的結果在第一批。
11. As a 讀者, I want 搜尋命中的專題列和菜譜列一起計入一批, so that 截斷依我實際看到的清單順序。
12. As a 讀者, I want 切換篩選後清單回到只顯示第一批, so that 新條件的清單從頭開始。
13. As a 讀者, I want 改搜尋字詞或清除搜尋後清單回到只顯示第一批, so that 不會沿用上一份清單的展開數量。
14. As a 讀者, I want 從菜譜頁按上一頁回到首頁時維持我已展開的數量, so that 我能回到剛才看到的位置繼續瀏覽。
15. As a 讀者, I want 上一頁回來時捲動位置也落在原處, so that 我不用重新往下找。
16. As a 讀者, I want 重新整理首頁時維持已展開的數量, so that 重整不會讓我失去瀏覽進度。
17. As a 讀者, I want 從別處以新連結進入首頁時只顯示第一批, so that 每次新造訪都從頭開始。
18. As a 讀者, I want 分享出去的首頁網址不帶展開數量, so that 網址維持目前的乾淨格式，只帶篩選與搜尋字詞。
19. As a 讀者, I want 菜譜減少後回到首頁時不會因保存的展開數量超過總數而出錯, so that 內容更新不影響瀏覽。
20. As a 鍵盤使用者, I want 按下按鈕後焦點移到新出現的第一道菜的連結, so that 我可以直接繼續往下讀，不用從按鈕再往回找。
21. As a 螢幕閱讀器使用者, I want 按鈕是可辨識的原生按鈕且文字說明剩餘數量, so that 我知道按下會發生什麼。
22. As a 螢幕閱讀器使用者, I want 被收起的列不會被朗讀, so that 我聽到的清單與畫面一致。
23. As a 未啟用 JavaScript 的讀者, I want 看到完整清單, so that 沒有腳本時不會有菜譜永遠看不到。
24. As a 手機讀者, I want 清單收起時首屏的位置不跳動, so that 頁面載入時不會晃一下。
25. As a 讀者, I want 清單依菜名排序與現在相同, so that 截斷不改變我熟悉的順序。
26. As a 寬螢幕讀者, I want 與手機相同的顯示更多行為, so that 不同裝置的規則一致。
27. As a 讀者, I want 篩選後清單沒有結果時仍顯示原本的空狀態訊息且沒有按鈕, so that 空狀態不被按鈕干擾。
28. As a 站主, I want 每批數量只在一處設定, so that 日後調整不必改多處。
29. As a 站主, I want 搜尋索引內容不受影響, so that 被收起的菜譜仍可被搜尋找到。
30. As a 站主, I want `pnpm measure:mobile` 能反映截斷後的頁面高度與列數, so that 之後談版面時量到的是讀者實際看到的樣子。
31. As a 開發者, I want 截斷規則是可單獨測試的純函式, so that 上下限與重設、還原邏輯不必靠瀏覽器測。
32. As a 開發者, I want 有一份以小批量建置的 e2e 站台專測顯示更多, so that 現有首頁與搜尋規格不必改動。

## Implementation Decisions

- **範圍只限首頁菜譜清單**。食材索引與收藏頁不套用。
- **每批 20 列**，第一批與之後每批相同。數量在建置時決定並寫進首頁標記，供腳本讀取；預設 20，可由建置環境變數覆寫，僅供 e2e 使用。
- **漸進增強**：建置輸出全部列且全部可見；腳本初始化時才收起超過的列。被收起的列以 `hidden` 隱藏，與現有篩選隱藏列的方式相同，因此不被朗讀。
- **截斷依目前顯示的清單順序計算**：沒有搜尋字詞時是依菜名排序並套用性質篩選後的列；有搜尋字詞時是 Pagefind 相關度排序後的菜譜列與專題列。截斷發生在現有 render 決定「哪些列可見、順序為何」之後，作為最後一步。
- **新增純函式模組（首頁工具內）**：輸入為可見列總數、每批數量、目前要顯示的數量（可為保存值或未設定）；輸出為實際顯示列數（夾在一批與總數之間）、剩餘列數、下一次按鈕要再顯示的數量。按一次按鈕的下一狀態也由純函式算出，並回傳新出現的第一列位置，供焦點移動使用。
- **重設時機**：讀者改變篩選或搜尋字詞時，顯示數量回到一批。現有寫網址的流程以 `history.replaceState` 清掉瀏覽紀錄狀態，這與重設一致；顯示更多寫入展開數量時必須保留目前網址，且寫網址時不得保留舊的展開數量。
- **還原**：展開數量存在目前這筆瀏覽紀錄的狀態（history state），不進網址、不進 sessionStorage。首頁初始化時若有保存值就套用，並夾在一批與目前總數之間；捲動位置交給瀏覽器的捲動還原，若需要則在列顯示後再交還捲動。
- **按鈕**：原生 `button`，位於清單之後，文字「再顯示 {n} 道（還有 {剩餘} 道）」。剩餘 0 時隱藏；清單為空時隱藏，空狀態訊息照舊。
- **焦點**：按下後焦點移到新出現的第一列的連結（菜譜或專題）。「共 N 道」狀態文字不變。
- **排序不變**：維持依菜名排序；不新增發布日期欄位。
- **量測腳本**：`measure:mobile` 的列數與頁面高度改為量測讀者看得到的列；報告另列總列數，方便比較。

## Testing Decisions

- 好的測試只驗證外部行為：給定總數與狀態，顯示幾列、按鈕文字為何、焦點落在哪；不檢查內部變數或 DOM 操作次數。
- **單元測試**：純函式的上下限（總數小於、等於、大於一批；最後一批不足；保存值超過總數或小於一批；未設定保存值），以及按一次的下一狀態與新出現的第一列位置。前例是現有首頁工具的單元測試（`parseHomeState`、`applyHomeState`）。
- **e2e：新增第三份站台**，沿用現有 `E2E_SITE=meal` 的模式。以預設 e2e 固定菜譜、每批 1 道（固定菜譜 4 道，讓按鈕文字至少更新幾次）建置到獨立輸出目錄與 port，只跑新的顯示更多規格；預設站台與其現有規格完全不動。測試涵蓋：初始只顯示 1 道並有按鈕；按下後多 1 道、焦點移到新出現的第一道、按鈕文字更新、到底後消失；切換篩選與改搜尋字詞後重設；進入菜譜頁再上一頁後維持展開數量；重新整理後維持；清單不足一批時沒有按鈕；停用 JavaScript 時全部可見。前例是 `meal.spec.ts` 與其專用站台。
- 指令 `pnpm test:e2e` 依序建置並跑三份站台；`pnpm check:merge --e2e` 亦同。

## Out of Scope

- 首屏空白（篩選列在 460px、第一列在 774px）另開一案。
- 頁碼、無限捲動、靜態多頁輸出。
- 改變清單排序或新增菜譜發布日期欄位。
- 食材索引、收藏頁、專題索引套用顯示更多。
- 把展開數量寫進網址或分享連結。

## Further Notes

- 量測依據：2026-10-08 在 `main`（6db9e46）以 `pnpm measure:mobile` 量得 390×844、68 列、列高 142px、一屏 5 列、頁面總高 10650px。
- 本功能之後要改回頁碼或調整每批數量都不難，不另立 ADR；理由記在本規格與 grill 紀錄。
