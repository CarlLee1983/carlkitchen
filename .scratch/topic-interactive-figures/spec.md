# 專題互動圖：炸花生時間軸試點

狀態：ready-for-agent。決策依據：[ADR 0011](../../docs/adr/0011-topic-interactive-figures.md)；用詞見 `GLOSSARY.md`〈互動圖〉。

## Problem Statement

站主寫專題時，有些小節講的是「隨時間改變的過程」，例如炸花生從冷油下鍋、小火慢炸、薄膜轉色到關火靠餘溫。手繪插畫只能定格在一個瞬間，讀者要靠文字在腦中把各階段串起來；站主想用 anatomy 風格的等角互動圖，讓讀者拖動時間親眼看過程，增加專題的精彩度。但專題目前只支援純 Markdown 與靜態圖片，也沒有規則保證圖上的內容和正文一樣只取核准來源的事實。

## Solution

在專題正文加入「互動圖」：以 `figure` 程式碼區塊引用一個圖識別值，建置時換成一張配合站上畫風的等角 SVG 圖，附滑桿、播放鈕、帶膜／去膜切換、即時讀數與全部階段清單。圖上每項事實寫在專題資料夾的 `.figure.yaml`，並在來源紀錄對照核准來源，由內容檢查把關。試點只在〈熱鍋與起鍋油〉的「炸花生從冷油開始」小節放一張，既有插畫保留。

## User Stories

1. 身為讀者，我想在〈熱鍋與起鍋油〉拖動時間滑桿看炸花生的過程，以便理解每個階段鍋裡會發生什麼。
2. 身為讀者，我想按播放鈕讓時間自動從 0 走到 12 分鐘，以便不用手動拖也能看完整過程。
3. 身為讀者，我想在播放中隨時拖動滑桿或再按一次暫停，以便停在我想細看的階段。
4. 身為讀者，我想看到即時讀數說明目前是哪個階段（冷油蓋過花生開小火、冒小泡與蒸氣並有劈啪聲、薄膜轉深紅褐且劈啪聲停、最後 1 到 2 分鐘關火靠餘溫、撈起放涼後才酥脆），以便把畫面和判斷訊號對上。
5. 身為讀者，我想看到「7 到 12 分鐘」畫成時間軸上的區間帶，以便知道時間依顆粒大小而定，不是固定的一點。
6. 身為讀者，我想切換帶膜與去膜花生，以便看到兩種花生各自的熟度判斷（薄膜轉深紅褐／表面淡黃）。
7. 身為讀者，我想點階段清單的任一項就跳到該階段，以便快速比較不同時點。
8. 身為讀者，我想圖上不出現來源沒有的溫度數字，以便信任圖上的每項資訊。
9. 身為停用 JavaScript 的讀者，我想仍看到關鍵狀態的圖與完整階段清單，以便內容不缺漏。
10. 身為使用螢幕閱讀器的讀者，我想在操作滑桿或切換時聽到目前階段的播報，以便不看畫面也能跟上。
11. 身為使用螢幕閱讀器的讀者，我想圖有描述實際內容的替代文字與圖說，以便理解圖在表達什麼。
12. 身為只用鍵盤的讀者，我想用 Tab 與方向鍵操作滑桿、播放鈕、切換與階段清單，以便不用滑鼠也能操作。
13. 身為設定「減少動態」的讀者，我想圖不跑動畫、但仍能手動切換階段，以便閱讀不受干擾。
14. 身為手機讀者，我想圖在窄螢幕縮放到可讀且頁面不出現橫向捲動，以便正常閱讀。
15. 身為讀者，我想進入畫面時圖不自動播放，以便專心讀文章開頭與首字放大的段落。
16. 身為讀者，我想互動圖的配色與字體和站上手繪插畫協調，以便整篇閱讀感一致。
17. 身為讀者，我想站內搜尋結果不重複出現圖上的刻度與讀數，以便搜尋結果乾淨。
18. 身為站主，我想在 Markdown 只寫一個 `figure` 程式碼區塊加圖識別值就放進一張互動圖，以便寫作時不碰 HTML 或程式。
19. 身為站主，我想圖上的階段時間、狀態文字、替代文字與圖說寫在專題資料夾的 `.figure.yaml`，以便審稿時直接看到圖上所有文字與數字。
20. 身為站主，我想在來源紀錄用 `figures` 對照每張圖的核准來源網址，以便圖的事實和正文段落用同一套方式稽核。
21. 身為站主，我想引用不存在的圖識別值時建置直接失敗並指出專題與識別值，以便打錯字不會默默發布空白。
22. 身為站主，我想 `pnpm check:content` 擋下沒有 `.figure.yaml`、沒有 `figures` 對照、對照網址不在 `sources`、或資料夾裡沒被正文引用的孤兒 `.figure.yaml`，以便圖不會成為繞過來源規則的漏洞。
23. 身為站主，我想草稿專題的互動圖不出現在正式輸出，以便草稿內容不外洩。
24. 身為站主，我想既有的炸花生插畫照舊保留，以便互動圖是補充而不是取代。
25. 身為維護者，我想 anatomy kit 只複製用到的檔案進 repo、附 MIT 授權與上游 commit 紀錄，以便知道來源、可手動同步，且不多一個執行期依賴。
26. 身為維護者，我想網站不因互動圖引入 MDX、React／Preact 或 WebGL，以便建置與頁面負擔維持現狀。
27. 身為維護者，我想沒有放互動圖的專題頁不載入任何互動圖的 JS 與 CSS，以便其他頁面效能不受影響。
28. 身為維護者，我想 e2e 固定專題含一張互動圖、草稿固定專題也含一張，以便瀏覽器行為與草稿排除都有回歸測試。

## Implementation Decisions

- **用詞**：「互動圖」依 `GLOSSARY.md`；圖識別值格式同專題識別值（小寫英數字以連字號分隔）。試點圖識別值 `peanut-frying`。
- **嵌入語法**：正文以語言標記為 `figure` 的程式碼區塊引用，區塊內容只有一行圖識別值。專題既有的 hast 外掛（目前負責首字放大與正文圖尺寸）新增一步：遇到 `figure` 程式碼區塊，讀同專題資料夾的 `<圖識別值>.figure.yaml`，呼叫對應的繪圖模組，把整個 `pre` 換成互動圖的 HTML。找不到資料檔或繪圖模組時丟錯讓建置失敗，錯誤訊息含專題識別值與圖識別值。不用圖片語法，不引入 MDX 或 remark-directive。
- **圖資料檔（`.figure.yaml`）**：放在專題資料夾，與 `topic.md` 同層，以 schema 驗證。欄位概念：`alt`（描述圖中實際內容）、`caption`（圖說）、`duration`（時間軸總長，分鐘）、`keyStage`（無 JS 時畫的階段）、`variants`（試點為帶膜／去膜，各有顯示名稱）、`stages`（有序；每個階段有起訖時間或區間、讀數文字，可依 variant 給不同文字）。schema 只描述「時間軸型」互動圖；第二種型態出現時再擴充。
- **繪圖模組**：每張圖一個繪圖模組，輸入驗證過的圖資料，輸出靜態 HTML 字串（`figure` 元素，內含 SVG、控制項、讀數區、階段 `<ol>`、`figcaption`）。模組以複製進 repo 的 anatomy kit 畫等角炒鍋、油面、花生與氣泡；各階段以 SVG 內的狀態類別切換外觀，不在執行期重畫幾何。
- **anatomy kit**：只複製試點用到的核心（等角相機、實體、SVG 字串渲染與其 CSS）到 vendor 目錄，附上游 `LICENSE` 與 README（上游網址、commit、複製了哪些檔、手動同步方式）。不改 kit 幾何程式；畫風只覆寫 CSS 變數層，改用站上的米白底、字體與強調色。網站只有淺色主題，只對一套 token。
- **執行期互動**：一段原生 JS，只在含互動圖的頁面載入。功能：滑桿（時間）、播放／暫停鈕（約 6 秒走完全程，到底自動停）、帶膜／去膜切換、點階段清單項目跳到該階段、讀數區 `aria-live="polite"` 播報目前階段。不自動播放；`prefers-reduced-motion: reduce` 時播放鈕改為逐階段跳轉、不做補間動畫。
- **無 JS 狀態**：伺服端輸出的 SVG 預設畫 `keyStage`（試點為 7 到 12 分鐘薄膜轉色），階段 `<ol>` 以一般 HTML 常駐顯示；滑桿與播放鈕在 JS 載入前隱藏或停用，不出現無作用的控制項。
- **搜尋索引**：互動圖的控制項、讀數與階段清單加 `data-pagefind-ignore`，只有 `figcaption` 進索引。
- **來源紀錄**：專題來源紀錄新增選填的 `figures` 陣列，每筆 `id`（圖識別值）與 `urls`（須列在 `sources`）。試點對照 The Woks of Life〈Wok-Fried Peanuts〉與 Omnivore's Cookbook〈Szechuan Spicy Peanuts〉，以實際用到的事實為準。
- **內容檢查**：專題檢查新增：已發布專題正文引用的每個圖識別值都有 `.figure.yaml` 且通過 schema、在 `figures` 有對照、對照網址都在 `sources`；專題資料夾裡沒被正文引用的 `.figure.yaml` 視為孤兒並報錯；草稿專題的互動圖內容不得出現在建置輸出（沿用既有草稿洩漏檢查的做法）。
- **試點內容**：〈熱鍋與起鍋油〉「炸花生從冷油開始」小節，在既有插畫附近插入 `figure` 區塊；正文文字不改。圖上只放來源有的事實：冷油蓋過花生後開小火、約 7 到 12 分鐘、冒小泡與蒸氣、劈啪聲、帶膜薄膜轉深紅褐且劈啪聲停／去膜表面淡黃、最後 1 到 2 分鐘可關火靠餘溫、放涼後才酥脆。不標溫度。

## Testing Decisions

- 好的測試只驗證外部行為：Markdown 進去、HTML 出來；內容資料夾進去、問題清單出來；瀏覽器裡讀者看得到、操作得到的東西。不測 SVG 幾何座標、CSS 類別名稱或 kit 內部函式。
- **Markdown 轉換**（沿用 topic-markdown 單元測試的 satteri 渲染）：含 `figure` 區塊的輸入產出 `figure` 元素，內含 `keyStage` 狀態的 SVG、全部階段的 `<ol>`、`figcaption`、替代文字與 `data-pagefind-ignore`；引用不存在的識別值丟錯；普通程式碼區塊不受影響；既有首字放大與正文圖行為不變。
- **內容檢查**（沿用 `runContentChecks` 與專題內容檢查的固定資料寫法）：缺 `.figure.yaml`、schema 不符、缺 `figures` 對照、對照網址不在 `sources`、孤兒 `.figure.yaml`、草稿專題的圖內容出現在輸出，各自回報對應問題；合法資料回傳空清單。
- **瀏覽器**（沿用固定站台 Playwright，前例 `topic-editorial.spec.ts`、`a11y.spec.ts`、`mobile-list.spec.ts`）：固定專題 `knife-skills` 加一張互動圖（資料標「固定資料」，沿用 `peanut-frying` 繪圖模組），`draft-topic` 也加一張。驗證：拖滑桿與按播放時讀數更新且 `aria-live` 內容改變；帶膜／去膜切換改變讀數；點階段清單跳到該階段；鍵盤可操作；停用 JS 時看得到關鍵狀態與清單且無無作用控制項；reduced-motion 時無補間動畫；手機寬度無橫向捲動；a11y 檢查通過；沒有互動圖的專題頁不載入互動圖 JS；草稿固定專題的圖不在正式站台。
- 真實內容：既有的真實資料測試或 `pnpm check:content` 對正式內容跑過，確認〈熱鍋與起鍋油〉的圖對照完整。

## Out of Scope

- 修改 `topic-writing` skill、`AGENTS.md` 的寫作規則（站主在預覽站確認試點後另開票）。
- 試點以外的專題或第二張互動圖；時間軸以外的互動圖型態。
- 〈用筷子看油溫〉的油溫圖（來源沒有冒泡程度對應的溫度）。
- WebGL 著色器、3D 旋轉、深色主題。
- 修改〈熱鍋與起鍋油〉正文文字或既有插畫。
- 自動同步上游 anatomy。
