# 季節與議題專題：規格

狀態：站主於 2026-10-08 確認方案並核准五個來源。網站入口、兩道菜譜與專題草稿已完成，待站主審閱；未推送或部署。

本紀錄由 2026-10-08 的 grill-with-docs 討論整理。既有專題格式與功能沿用 `.scratch/topics/spec.md`；本次討論擴充選題與編輯方式。

## 已確認

- 專題可以從季節、節慶或生活議題切入飲食文化，以文化帶入、協助讀者選擇料理為目的。
- 首篇先介紹飲食文化與烹調。民間習俗與健康功效分開；若未來納入健康功效，另行查證並決定範圍。
- 先用一篇驗證文章搭配菜譜的方式，記錄可重用的原則，再決定後續功能。
- 首篇暫定題目為〈天涼了，煮一鍋：台灣補冬文化與家常料理〉，採每年都能閱讀的內容，避免只適用於某一年的時事敘述。
- 首篇新增麻油雞與薑母鴨菜譜；「燒油雞」依站主接受的建議暫按「麻油雞」理解。
- 羊肉爐可以在文化段落提及，完整菜譜後續再補；一般火鍋另留一篇。
- 正文介紹料理時提供特色、選擇理由與完整菜譜連結，不重寫完整步驟；同一道菜譜可被不同專題引用。
- 使用獨立 worktree `CarlKitchen-topics`、分支 `docs/topics-autumn-winter` 記錄文件。
- 文化專題採「文化背景 → 料理特色與差異 → 怎麼選 → 前往菜譜」的篇章結構。選菜依據優先談口味、主要食材、準備時間與器材；文化說法也須逐節記錄來源對照。
- 麻油雞與薑母鴨菜譜先送審；兩道菜譜發布後再發布專題。文章可以同步準備草稿，羊肉爐只介紹，不放尚未存在的菜譜連結。
- 入口範圍已選定：首頁由站主指定推薦專題；菜譜頁依既有專題與菜譜關聯呈現相關專題。暫不新增專題分類或篩選。
- 首頁一次推薦一篇。
- 菜譜頁顯示最多三篇已發布的相關專題，按發布日期由新到舊排列，呈現標題與短介。
- 首頁推薦由站主安排檔期，瀏覽器在讀者開啟首頁時依台北日期選出一篇已發布專題；不增加定時部署。未執行 JavaScript 時呈現常青備選。裝置日期不正確可能選錯檔期，搜尋引擎可能只看到常青版本；站主已接受這項取捨。
- 沒有當期專題時顯示站主指定的常青備選；沒有備選時隱藏推薦區。
- 檔期重疊時依站主指定的推薦優先順序選題，較短的節慶檔期可以覆蓋季節推薦，結束後回到季節推薦。
- 季節檔期使用每年重用的月份與日期；中秋等每年日期不同的節慶先按年度設定起訖日，不自動推算農曆。
- 首頁推薦放在介紹下方、菜譜篩選之前，以精簡的「本期專題」呈現小封面、標題與短介；保留既有隨機菜譜大圖。
- 首篇每年 11 月 1 日至翌年 1 月 31 日推薦，起訖日均含當日。這是編輯檔期，不代表習俗的統一日期。
- 常青備選採現有〈備菜與預處理〉（`prep-basics`）。首篇與兩道菜譜尚未發布前不加入有效推薦檔期，首頁顯示備選。

## 現有基礎與限制

原工作分支落後於主線；重新取得最新 `origin/main` 後確認，網站已有專題集合、頁面、搜尋與內容檢查。本次不需另建專題內容模型。

既有 `topic-writing` 以料理原理為中心，要求每節包含原則、機制及判斷訊號。已確認文化專題採不同篇章結構，後續需同步調整寫作指引；不得為了套格式捏造文化成因或料理判斷。

菜譜與專題均須先取得站主核准來源。現階段未核准任何新來源，亦未撰寫文化或料理事實。既有專題相關連結只允許指向已發布頁面，正式內容的發布順序須遵守此限制。

## 確認與來源核准

產品決策已由站主確認。來源候選依既有 `topic-writing` 與 `recipe-making` 整理：逐一確認可讀、提供網址與摘要，站主核准具體網址後才擷取事實、撰寫文化文章或菜譜。「照建議」不視為核准尚未提出的來源。

## 設計分析

首頁既有讀取專題與搜尋結果的流程，但推薦區需與搜尋隱藏列及菜譜篩選分開，避免推薦專題影響菜譜數量或篩選結果。瀏覽器端以共用的日期選題函式切換，卡片固定尺寸，減少畫面跳動；靜態 HTML 保留可閱讀的常青備選，腳本執行前可能短暫顯示備選。

菜譜頁從專題的 `relatedRecipes` 反向查找，不在菜譜中新增另一份關聯欄位。只列已發布專題，無結果時省略整區；日期相同時以識別值提供穩定排序。

檔期資料須涵蓋跨年期間、年度特定期間、優先順序與常青備選。日期格式、無效日期、重複順位、草稿或不存在的目標應在內容檢查阻擋；具體儲存格式由實作依現有架構選擇，不在此綁定。尚未發布的專題不預先加入有效檔期。預設在載入時選題，已開啟頁面不承諾午夜即時切換。

驗收涵蓋開始／結束日、跨年、重疊、無當期文章、沒有備選、停用 JavaScript、草稿排除、菜譜關聯與搜尋篩選不受影響。手機首頁仍需量測與檢查版面，不先臆測新增區塊的高度。

## 依賴順序與驗收

1. 更新 `topic-writing` 的適用範圍與篇章指引，保留技巧專題原有結構，新增文化專題寫法；來源核准、段落對照、臺灣用詞及去 AI 味規則沿用。
2. 先寫日期選題與反向關聯的失敗測試，再實作首頁推薦和菜譜頁相關專題；使用已發布專題與固定測試內容即可驗證，不依賴新菜譜完成。
3. 為補冬文化、麻油雞、薑母鴨整理來源候選並取得核准。核准後製作兩道菜譜，同步準備專題草稿及封面。
4. 兩道菜譜由站主審閱發布後，專題才送審發布；最後啟用首篇檔期。代理不得合入或真實部署。

可觀察的完成條件：

- 台北日期 11/1 與 1/31 皆命中補冬檔期；10/31 與 2/1 回到備選。跨年不影響判斷，年度節慶檔期不會自動套到其他年份。
- 重疊時顯示順位較高的文章，結束後回到仍有效的季節推薦；無候選且無備選時推薦區不存在。
- 正式首頁不輸出草稿候選；未執行 JavaScript 時可看到常青備選，既有搜尋與菜譜篩選的結果及數量不變。
- 麻油雞、薑母鴨頁面能找到補冬專題；不相關菜譜不出現該連結。相關專題最多三篇、只含已發布內容，依發布日期及識別值穩定排序，空集合不顯示區塊。
- 手機量測與瀏覽器驗證涵蓋推薦區、找菜入口和首列菜譜位置，不放寬既有首屏要求來掩蓋版面退步。
- 文章文化說法逐節對應核准來源，料理特色與準備資訊能對應菜譜或來源，不寫療效、不重寫完整菜譜步驟、不替站主捏造心得。
- 正式內容的封面與菜譜各圖符合既有圖片規格；相關連結沒有未發布目標。

實作與內容送審前跑既有完整 gates：`pnpm check`、`pnpm test`、`pnpm test:e2e`，正式建置後跑 `pnpm check:content`；開 PR 或推送更新前跑 `pnpm check:merge`。依菜譜製作流程另記錄 `--launch` 結果，不修改門檻。
