# 專題寫作

專題是一篇跨越多道菜的料理知識文章，可以談原理、技巧、觀念，或季節與議題相關的飲食文化。外部文章只是**選題參考**，用來決定題目與架構；直接從季節或議題選題時不必另找選題參考，`references` 填空陣列。每一項事實仍須有**核准來源**，並記在內部來源紀錄。詞彙見 [GLOSSARY.md](../../../GLOSSARY.md)，整體設計見[專題規格](../../../.scratch/topics/spec.md)。

欄位、來源紀錄與檢查規則不在這裡重抄，以這些檔案為準：

- 專題欄位：[topic-schema.ts](../../../src/content/topic-schema.ts)；內容放 `content/topics/<識別值>/topic.md`，封面圖放同資料夾
- 來源紀錄：[topic-sources.ts](../../../src/content/topic-sources.ts)；內容放 `content/topic-sources/<識別值>.yaml`
- 檢查項目：[topics.ts](../../../src/content-checks/topics.ts)
- 範例：`tests/fixtures/topics/` 與 `tests/fixtures/topic-sources/`

文字語氣與去 AI 味的規則見 [de-ai-voice](../de-ai-voice/SKILL.md)；用詞表見 [recipe-writing](../recipe-writing/SKILL.md)〈用詞〉。

## 步驟

1. **確認選題與範圍**：有選題參考時先讀完，再決定專題識別值（小寫英數字以連字號分隔）、題目與篇章類型（技巧或文化）。長篇參考依主題拆篇；完整料理示範交給 [recipe-making](../recipe-making/SKILL.md) 做成菜譜，專題只連過去。依〈正文插畫與首字放大〉規畫各主要小節的插畫位置與要解釋的內容。完成條件：向站主回報每篇識別值、題目、涵蓋範圍、相關菜譜與插畫安排並取得確認。
2. **取得核准來源**：技巧專題優先找食品科學、食品安全機構、出版社或食譜站；文化專題優先找文化機構、地方政府及直接記錄習俗的公開資料，料理資訊另找菜譜來源。逐一打開確認可讀、確實支持預計陳述的事實。選題參考本身不列為候選。照 [sourcing.md](../recipe-making/sourcing.md)〈提候選清單〉的做法，附一行摘要請站主勾選，**停下等站主**。完成條件：站主勾選的網址已寫入來源紀錄的 `sources`。
3. **逐條查證並填段落對照**：把預計涵蓋的原理、文化背景、料理特色及數字拆成待查陳述；有選題參考時，也核對其中預計採用的說法。到核准來源找依據，有依據的記入來源紀錄 `sections`，查不到依據的陳述刪掉或修正，並在回報列出「刪了什麼、為什麼」。來源之間衝突時選一種口徑，回報取捨。完成條件：每項要寫進專題的陳述都對得上某個核准來源；`sections` 的 `heading` 與稍後內文的 `##`／`###` 標題純文字**逐字相同**。
4. **撰寫**：依〈篇章結構〉的適用分支與〈寫法〉寫 `topic.md`，並填 frontmatter：`draft: true`、`editorialLayout: true`、`references` 放選題參考的作者、標題、網址（沒有選題參考時填 `[]`；公開的選題參考不得同時是核准來源）、`relatedRecipes`／`relatedIngredients` 只連確實談到的內容。閱讀版面依〈正文插畫與首字放大〉，文化專題同樣適用。完成條件：每個小節標題都出現在 `sections`，標題不用行內格式（粗體、連結、程式碼）。
5. **跑 de-ai-voice**：整篇依 [de-ai-voice](../de-ai-voice/SKILL.md) 處理一次。完成條件：該 skill 的自查清單全部成立。
6. **自查與版面驗收**：逐項完成〈自查清單〉；完成封面與正文插畫後，以桌機、手機預覽實際文章，保存畫面確認插畫位置、首字繞排與文字可讀。不成立就回到對應步驟。
7. **維持草稿，送審 PR**：草稿留在本地工作分支，準備好才推送並開 PR，不合入、不改 `draft`；合入是站主的發布核准。PR 說明附：來源取捨、刪掉或修正的原理、臺灣用詞對照（見〈臺灣用詞〉）、去 AI 味改了什麼。

## 篇章結構

### 文化專題

依「文化背景 → 料理特色與差異 → 怎麼選 → 前往菜譜」組織文章。選菜依據優先談口味、主要食材、準備時間與器材，資訊須對應核准來源或相關菜譜。民間的食補說法寫成習俗，不延伸成療效或體質建議；文化段落也須記錄來源對照，不硬套熱或食材變化的機制。

介紹料理時在正文提供菜譜連結，不重寫完整步驟；只連已發布菜譜。需要新增菜譜時，文章可以同步準備草稿，但待相關菜譜發布後才送審專題。每篇約 1,500 到 3,000 字，開頭直接進入主題，不寫空泛的總結段。

### 技巧專題

每個 `##` 小節講一項原理，內文依序涵蓋四件事，寫成連貫的段落，不把四塊切成標籤：

1. **原則**：這一節的結論，一兩句。
2. **原因**：背後的機制（食材或熱的變化），只寫核准來源支持的說法。
3. **怎麼做與怎麼判斷**：具體動作，以及讀者看得到、聽得到或可計時的判斷訊號（沿用菜譜的熟度訊號寫法）。來源沒有的訊號標為待補，不用推測補齊。
4. **相關菜譜**：段尾用一句話連到已發布、確實用到這項原理的菜譜（`/recipes/<識別值>/`）；沒有合適菜譜就省略這句。

整篇約 1,500 到 3,000 字，超過就拆成兩篇；開頭一兩段直接進入主題，不寫總結段。多個小節各有子主題時可用 `###`。

## 寫法

- 用自己的句子重述來源的事實；不沿用選題參考或來源的原句、段落結構與口訣措辭。
- 以「這道手法」「做法」「食材」為主詞，不寫第一人稱經驗，不宣稱試作、保證成功或寫療效。
- 個人心得只能由站主撰寫；代理不替站主補心得、不模擬站主的口吻。站主有心得時，在回報指出放在哪一節的哪個位置，由站主自己寫入。
- 數值（溫度、時間、比例）一律照核准來源，連同其適用條件一起寫；來源沒給的數字不補。

## 臺灣用詞

站主指定這是撰文最重要的一點：**食材、調味料、廚具與烹調動作一律用臺灣用詞**。選題參考與來源常是中國用語，寫的時候逐項轉換。

以 [recipe-writing](../recipe-writing/SKILL.md)〈用詞〉的表為準，並補充選題參考常見的詞。下表是補充，與 recipe-writing 或 `content/` 已發布菜譜的用法衝突時，以後者為準；拿不準的詞列進 PR 說明請站主定奪：

| 原文詞         | 採用詞   |
| -------------- | -------- |
| 焯水           | 汆燙     |
| 腌、腌制       | 醃、醃漬 |
| 出鍋           | 起鍋     |
| 肉末、肉餡     | 絞肉     |
| 料酒           | 米酒     |
| 生抽           | 醬油     |
| 雞精           | 雞粉     |
| 蒜蓉           | 蒜末     |
| 小蔥、香蔥     | 青蔥     |
| 電飯煲、電飯鍋 | 電子鍋   |
| 高壓鍋         | 壓力鍋   |
| 案板           | 砧板     |
| 一勺（量匙）   | 一湯匙   |

完成條件：全文找不到對岸說法，且 PR 說明附一份「來源詞 → 採用詞」對照（只列這篇實際轉換過的詞）。同一樣東西全篇只用一個名稱。

## 正文插畫與首字放大

技巧與文化專題都採同一閱讀原則：正文穿插插畫，文章開頭第一段啟用首字放大。除非站主明確指定另一種版面，新增或改寫專題一律填 `editorialLayout: true`，不因題材是文化介紹而改用純文字版面。

### 正文插畫

- 依主要小節安排多張插畫，分散放在確實解釋該圖的段落附近；整篇不得只有封面，或把全部圖集中在文末。小節的操作、食材差異與料理比較優先用圖呈現，不用重複成品圖填數量。
- 每張圖在大綱中寫明「所在小節、幫讀者看懂什麼、對應的來源事實」，再生成獨立插畫。文化題材也以有依據的料理與食材呈現，不畫來源未支持的歷史場景、儀式或器材操作。
- 圖片放在 `topic.md` 同資料夾，以標準 Markdown 相對路徑插入，例如 `![描述圖中實際內容](./ginger-preparation.webp)`。替代文字描述可見材料或狀態，不用「示意圖」帶過。
- 封面與正文插畫同一畫風，構圖與流程各見下方〈插畫製作〉。既有版面會保持正文圖片比例與響應式寬度，不手寫 HTML、固定尺寸或額外 CSS。

### 開頭首字

`editorialLayout: true` 使用既有 [Markdown 處理](../../../src/markdown/topic-markdown.ts)與[專題版面](../../../src/pages/topics/[id].astro)，只放大正文開頭第一段的首個中文字。開頭引號等標點維持一般大小；寬螢幕首字約占兩行、後文繞排，手機回到正常字級與行內排列。不是每個段落或每個小節都放大，也不放大標題、短介。

正文用自然中文起頭即可，不插入手工首字標籤、空白或換行來湊效果。預覽時核對引用開頭、換行與放大文字後的閱讀順序，避免首字和圖片重疊、手機溢出。行為與驗收範例見 [topic-editorial.spec.ts](../../../e2e/topic-editorial.spec.ts)；圖文安排可參考〈[備菜與預處理](../../../content/topics/prep-basics/topic.md)〉。

## 插畫製作

### 封面

封面是意境風景，不是一道菜的成品圖。規格只寫在 `.scratch/recipe-mvp/issues/06-homepage-direction.md`〈專題封面〉：畫風沿用菜譜插畫，構圖改成產地或節令風景為主、前景小物點題。

1. **選景**：從內文找出這篇的產地、作物或季節，定下一個風景與一兩樣前景小物。完成條件：風景與小物都能指到內文某一段。
2. **寫構圖描述**：英文寫明風景（遠景、中景、近景各是什麼）、季節與天候、前景小物及其位置。不附參考圖；已有其他已發布專題封面時，可附一張作風格參考。
3. **產圖**：用菜譜的同一支腳本，以 `STYLE_FILE` 換成本 skill 的 [style.txt](style.txt)（風景風格段與禁止段）：

   ```sh
   STYLE_FILE=.claude/skills/topic-writing/style.txt \
     .claude/skills/recipe-making/scripts/gen.sh <scratchpad>/topics/<識別值> hero "<英文構圖描述>"
   ```

   逾時、重試與 PNG 只放 scratchpad 的規則同 [illustration.md](../recipe-making/illustration.md)〈產圖〉。

4. **目視檢查**：Read `.preview.jpg`，06〈專題封面〉與〈禁止事項〉每一條都成立，並把預覽圖縮到約 64 px 寬想像首頁縮圖，主體色塊仍分得出來。不符就重產，最多 3 次。
5. **轉檔**：`node .claude/skills/recipe-making/scripts/img.mjs webp <PNG> content/topics/<識別值>/hero.webp`。`hero.alt` 描述畫面實際內容（風景與前景小物），不提餐具。

### 正文插畫

正文插畫與菜譜插畫同一風格與規格：WebP、1536×1024、不超過 300 KB。流程照 [illustration.md](../recipe-making/illustration.md)〈寫構圖描述〉到〈轉檔〉，用預設風格檔（不設 `STYLE_FILE`），風格規格以 06〈圖片風格規格〉為準；PNG 原圖放 scratchpad，轉檔後存到 `content/topics/<識別值>/`。逐張生成、目視核對與轉檔，檔名描述該圖內容。構圖只畫來源支持的材料與操作狀態；同篇的食材切法、鍋具、線條與上色保持一致。正文的刀具等物件僅在操作本身需要時出現；不可把封面「不畫餐具」延伸成禁止必要的備料工具。

合入即發布，已發布專題必須有封面，所以送審 PR 要含封面。

## 自查清單

- [ ] 選題參考只用於題目與架構；每項事實都對得上核准來源，來源已列入 `sources`
- [ ] 選題參考放在 `references`，且不在核准來源裡
- [ ] `sections` 的每個 `heading` 逐字等於內文某個 `##`／`###` 標題的純文字，標題沒有行內格式
- [ ] 查不到依據的原理已刪除或修正，並在回報列出
- [ ] 技巧專題每節都有原則、原因、怎麼做與怎麼判斷；文化專題涵蓋背景、料理差異與選菜依據；相關菜譜只連已發布且確實相關的
- [ ] 全篇約 1,500 到 3,000 字，沒有任何句子與選題參考或來源原句相同或只換幾個字
- [ ] 沒有第一人稱、試作宣稱、療效或保證；沒有替站主寫的個人心得
- [ ] 食材、調味料、廚具與烹調動作全部是臺灣用詞，PR 說明有「來源詞 → 採用詞」對照
- [ ] 已跑 `de-ai-voice` 且其自查清單成立
- [ ] 封面是 06〈專題封面〉的意境風景、縮圖仍可辨，`hero.alt` 描述風景與前景小物且不提餐具
- [ ] 已按〈正文插畫與首字放大〉完成多張正文圖，分散在對應段落，品項、狀態與替代文字一致
- [ ] `editorialLayout: true`；桌機開頭首字繞排、標點正常，手機一般字級，放大文字後可讀；預覽畫面已核對
- [ ] `draft: true`，只留在工作分支，等站主審閱 PR
