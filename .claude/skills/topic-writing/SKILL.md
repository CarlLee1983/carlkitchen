# 專題寫作

專題是一篇跨越多道菜的料理知識文章（原理、技巧、觀念）。外部文章只是**選題參考**，用來決定題目與架構；專題裡每一項事實都要另有**核准來源**，並記在內部來源紀錄。詞彙見 [GLOSSARY.md](../../../GLOSSARY.md)，整體設計見[專題規格](../../../.scratch/topics/spec.md)。

欄位、來源紀錄與檢查規則不在這裡重抄，以這些檔案為準：

- 專題欄位：[topic-schema.ts](../../../src/content/topic-schema.ts)；內容放 `content/topics/<識別值>/topic.md`，封面圖放同資料夾
- 來源紀錄：[topic-sources.ts](../../../src/content/topic-sources.ts)；內容放 `content/topic-sources/<識別值>.yaml`
- 檢查項目：[topics.ts](../../../src/content-checks/topics.ts)
- 範例：`tests/fixtures/topics/` 與 `tests/fixtures/topic-sources/`

文字語氣與去 AI 味的規則見 [de-ai-voice](../de-ai-voice/SKILL.md)；用詞表見 [recipe-writing](../recipe-writing/SKILL.md)〈用詞〉。

## 步驟

1. **確認選題參考與範圍**：讀完選題參考，決定專題識別值（小寫英數字以連字號分隔）與題目。長篇參考依烹飪階段拆成多篇專題，每篇一個主題；參考裡的完整料理示範不寫進專題，交給 [recipe-making](../recipe-making/SKILL.md) 做成菜譜，專題只連過去。完成條件：向站主回報拆分方案（每篇的識別值、題目、涵蓋的原則清單）並取得確認。
2. **取得核准來源**：為這個專題找候選來源（權威食品科學、食品安全機構、出版社或食譜站的公開頁面），逐一打開確認可讀、確實談這個原理。選題參考本身不列為候選。照 [sourcing.md](../recipe-making/sourcing.md)〈提候選清單〉的做法，附一行摘要請站主勾選，**停下等站主**。完成條件：站主勾選的網址已寫入來源紀錄的 `sources`。
3. **逐條查證並填段落對照**：把選題參考的每項原理、口訣、數字拆成待查陳述，到核准來源找依據。有依據的記入來源紀錄 `sections`，查不到依據的陳述刪掉或修正，並在回報列出「刪了什麼、為什麼」。來源之間衝突時選一種口徑，回報取捨。完成條件：每項要寫進專題的陳述都對得上某個核准來源；`sections` 的 `heading` 與稍後內文的 `##`／`###` 標題純文字**逐字相同**。
4. **撰寫**：依〈每節結構〉與〈寫法〉寫 `topic.md`，並填 frontmatter：`draft: true`、`references` 放選題參考的作者、標題、網址（它會公開顯示，所以不得同時出現在核准來源）、`relatedRecipes`／`relatedIngredients` 只連確實談到的內容。完成條件：每個小節標題都出現在 `sections`，標題不用行內格式（粗體、連結、程式碼）。
5. **跑 de-ai-voice**：整篇依 [de-ai-voice](../de-ai-voice/SKILL.md) 處理一次。完成條件：該 skill 的自查清單全部成立。
6. **自查**：逐項完成〈自查清單〉；封面依〈封面〉產出。不成立就回到對應步驟。
7. **維持草稿，送審 PR**：草稿留在本地工作分支，準備好才推送並開 PR，不合入、不改 `draft`；合入是站主的發布核准。PR 說明附：來源取捨、刪掉或修正的原理、臺灣用詞對照（見〈臺灣用詞〉）、去 AI 味改了什麼。

## 每節結構

每個 `##` 小節講一項原理，內文依序涵蓋四件事，寫成連貫的段落，不把四塊切成標籤：

1. **原則**：這一節的結論，一兩句。
2. **原因**：背後的機制（食材或熱的變化），只寫核准來源支持的說法。
3. **怎麼做與怎麼判斷**：具體動作，以及讀者看得到、聽得到或可計時的判斷訊號（沿用菜譜的熟度訊號寫法）。來源沒有的訊號標為待補，不用推測補齊。
4. **相關菜譜**：段尾用一句話連到已發布、確實用到這項原理的菜譜（`/recipes/<識別值>/`）；沒有合適菜譜就省略這句。

整篇約 1,500 到 3,000 字，超過就拆成兩篇；開頭一兩段直接進入主題，不寫總結段。多個小節各有子主題時可用 `###`。

## 寫法

- 用自己的句子重述來源的事實；不沿用選題參考或來源的原句、段落結構與口訣措辭。
- 以「這道手法」「做法」「食材」為主詞，不寫第一人稱經驗，不宣稱試作、保證成功或寫療效。
- 個人心得只能由站主撰寫；代理不替站主補心得、不模擬站主的口吻。站主有心得時，在回報指出放在哪一節的哪個位置，由站主自己寫入。
- 數值（溫度、時間、比例）一律照核准來源，連同其適用條件一起寫；來源沒給的數字不補。

## 臺灣用詞

站主指定這是撰文最重要的一點：**食材、調味料、廚具與烹調動作一律用臺灣用詞**。選題參考與來源常是中國用語，寫的時候逐項轉換。

以 [recipe-writing](../recipe-writing/SKILL.md)〈用詞〉的表為準，並補充選題參考常見的詞。下表是補充，與 recipe-writing 或 `content/` 已發布菜譜的用法衝突時，以後者為準；拿不準的詞列進 PR 說明請站主定奪：

| 原文詞         | 採用詞   |
| -------------- | -------- |
| 焯水           | 汆燙     |
| 腌、腌制       | 醃、醃漬 |
| 出鍋           | 起鍋     |
| 肉末、肉餡     | 絞肉     |
| 料酒           | 米酒     |
| 生抽           | 醬油     |
| 雞精           | 雞粉     |
| 蒜蓉           | 蒜末     |
| 小蔥、香蔥     | 青蔥     |
| 電飯煲、電飯鍋 | 電子鍋   |
| 高壓鍋         | 壓力鍋   |
| 案板           | 砧板     |
| 一勺（量匙）   | 一湯匙   |

完成條件：全文找不到對岸說法，且 PR 說明附一份「來源詞 → 採用詞」對照（只列這篇實際轉換過的詞）。同一樣東西全篇只用一個名稱。

## 封面

封面插畫與菜譜成品圖同一風格與規格：手繪水彩、WebP、1536×1024、不超過 300 KB，不畫餐具。流程照 [illustration.md](../recipe-making/illustration.md)〈寫構圖描述〉到〈轉檔〉，用同一組腳本（`scripts/gen.sh`、`scripts/img.mjs`），風格規格以 `.scratch/recipe-mvp/issues/06-homepage-direction.md`〈圖片風格規格〉為準。專題沒有材料清單，構圖描述改寫這篇主題的核心食材或動作；PNG 原圖放 scratchpad，轉檔後存為 `content/topics/<識別值>/hero.webp`。`hero.alt` 描述畫面實際內容，不提餐具。

合入即發布，已發布專題必須有封面，所以送審 PR 要含封面。

## 自查清單

- [ ] 選題參考只用於題目與架構；每項事實都對得上核准來源，來源已列入 `sources`
- [ ] 選題參考放在 `references`，且不在核准來源裡
- [ ] `sections` 的每個 `heading` 逐字等於內文某個 `##`／`###` 標題的純文字，標題沒有行內格式
- [ ] 查不到依據的原理已刪除或修正，並在回報列出
- [ ] 每節都有原則、原因、怎麼做與怎麼判斷；相關菜譜只連已發布且確實相關的
- [ ] 全篇約 1,500 到 3,000 字，沒有任何句子與選題參考或來源原句相同或只換幾個字
- [ ] 沒有第一人稱、試作宣稱、療效或保證；沒有替站主寫的個人心得
- [ ] 食材、調味料、廚具與烹調動作全部是臺灣用詞，PR 說明有「來源詞 → 採用詞」對照
- [ ] 已跑 `de-ai-voice` 且其自查清單成立
- [ ] 封面符合規格、`hero.alt` 不提餐具
- [ ] `draft: true`，只留在工作分支，等站主審閱 PR
